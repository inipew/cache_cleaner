# 4. Safety menjadi first-class citizen

Ini menurut saya perubahan paling penting.

Saat ini repository sudah punya `rules.rs`, fd-relative walker, mount boundary check, FBE awareness, dan `SO_PEERCRED` RBAC. ([GitHub][1])

Pada rewrite, saya akan membuat:

```text
safety/
```

sebagai **lapisan wajib sebelum executor**.

Flow:

```text
Candidate
   │
   ▼
┌──────────────┐
│ Path Guard   │
└──────┬───────┘
       ▼
┌──────────────┐
│ Mount Guard  │
└──────┬───────┘
       ▼
┌──────────────┐
│ Type Guard   │
└──────┬───────┘
       ▼
┌──────────────┐
│ Age Policy   │
└──────┬───────┘
       ▼
┌──────────────┐
│ User/FBE     │
└──────┬───────┘
       ▼
┌──────────────┐
│ Runtime State│
└──────┬───────┘
       ▼
     ALLOW
```

Dan **tidak ada jalan bypass**.

Misalnya:

```rust
executor.delete(candidate)
```

seharusnya bahkan tidak menjadi API publik.

Lebih bagus:

```rust
executor.execute(plan)
```

dan `Plan` hanya bisa dibuat setelah policy validation.

Secara konseptual:

```rust
RawCandidate
    ↓
ValidatedCandidate
    ↓
CleanupPlan
    ↓
CleanupResult
```

Ini memanfaatkan type system Rust untuk mencegah programmer sendiri membuat operasi berbahaya.

# 49. Flow cleaning yang saya rekomendasikan

Secara kode:

```rust
pub fn clean(request: CleanRequest) -> Result<CleanResult> {
    let context = runtime.snapshot()?;

    scheduler.ensure_allowed(&context)?;

    let candidates = scanner.scan(&request)?;

    let validated = safety.validate(candidates, &context)?;

    let plan = planner.build(validated, &request)?;

    let result = executor.execute(plan)?;

    verifier.verify(&result)?;

    reporter.report(&result);

    Ok(result)
}
```

Itulah kira-kira **"spine"** seluruh project.

Perhatikan bahwa setiap bagian punya satu tanggung jawab:

```text
runtime    → kondisi
scheduler  → boleh mulai?
scanner    → apa yang ada?
safety     → aman atau tidak?
planner    → apa yang akan dilakukan?
executor   → lakukan
verifier   → benar-benar berhasil?
reporter   → laporkan
```

Menurut saya ini jauh lebih sehat daripada membiarkan `engine` menjadi tempat berbagai macam logic.
