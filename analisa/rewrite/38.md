Scanner Architecture, Directory Traversal Contract, dan Candidate Discovery

Scanner adalah subsystem yang bertugas menemukan resource yang berpotensi menjadi cleanup candidate.

Scanner tidak menentukan apakah resource boleh dihapus.

Scanner tidak melakukan deletion.

Scanner tidak membuat authorization.

Scanner hanya melakukan discovery berdasarkan Target Catalog, JobContext, ScanBudget, dan filesystem abstraction.

Output scanner adalah kumpulan Candidate yang masih harus melewati Safety dan Policy.

Prinsip utama scanner

Scanner harus bersifat read-only.

Scanner tidak boleh mengubah filesystem.

Scanner tidak boleh mengikuti symlink secara default.

Scanner tidak boleh keluar dari TrustedRoot.

Scanner harus menghormati scan budget.

Scanner harus dapat berhenti karena cancellation.

Scanner harus mampu menangani filesystem yang berubah selama traversal.

Scanner harus menganggap seluruh hasil discovery sebagai snapshot sementara.

Scanner tidak boleh menganggap metadata yang ditemukan saat scan masih benar ketika execution dimulai.

Boundary scanner

Input scanner:

JobContext

CatalogSnapshot

TargetDescriptor

ScanPolicy

ScanBudget

CancellationToken

Filesystem abstraction

Clock jika diperlukan

Output scanner:

CandidateStream atau CandidateSet

ScanReport

ScanResult

Scanner tidak menerima raw client path.

Scanner menerima target yang sudah berasal dari Target Catalog.

Target resolution

Sebelum scanner berjalan, TargetId harus di-resolve melalui CatalogSnapshot.

Jika target tidak ditemukan:

ScanResult::TargetUnavailable.

Jika target ditemukan tetapi locked:

ScanResult::Deferred atau TargetUnavailable sesuai kondisi.

Jika target root identity tidak dapat diverifikasi:

ScanResult::Stale.

Jika target tidak diizinkan profile:

scanner tidak boleh mencoba scanning.

Policy admission sebaiknya dilakukan sebelum scan apabila policy dapat menentukan bahwa target sama sekali tidak relevan.

Namun candidate-level policy tetap dilakukan setelah discovery karena scanner belum mengetahui seluruh informasi candidate.

TrustedRoot

Scanner tidak boleh melakukan traversal menggunakan absolute path concatenation.

Scanner harus bekerja relatif terhadap trusted root.

Conceptual traversal:

TrustedRoot

→ root directory handle

→ child entry

→ validated relative path

→ metadata

→ Candidate

Filesystem abstraction harus menyediakan API yang mempersulit penggunaan unsafe traversal.

Jangan menyediakan scanner dengan API seperti:

scan("/data/user/0/...")

Lebih baik:

scan(target_descriptor)

Target descriptor sudah mengandung root reference yang dibuat platform/catalog layer.

Directory traversal

Traversal harus menggunakan directory descriptor atau equivalent secure abstraction.

Untuk setiap directory:

baca entry.

validasi nama entry.

buat RelativePath.

ambil metadata tanpa mengikuti symlink jika platform mendukung.

validasi filesystem identity.

kemudian tentukan apakah entry perlu direkursi.

Directory recursion tidak boleh dilakukan berdasarkan string path semata.

Contoh konsep yang harus dihindari:

current_path = current_path + "/" + entry_name

lalu:

stat(current_path)

Pendekatan tersebut membuka ruang race dan traversal ambiguity.

Lebih aman menggunakan parent directory handle dan relative entry name.

Entry name validation

Entry name dari filesystem harus diperlakukan sebagai untrusted data.

Entry harus divalidasi sebelum menjadi PathComponent.

Invalid entry harus menghasilkan:

RejectedEntry

atau

ScanWarning

dan tidak boleh menyebabkan scanner crash.

Entry name yang mengandung:

NUL

separator yang tidak valid

encoding invalid

atau format yang tidak dapat direpresentasikan

harus ditangani secara defensive.

Parent traversal

Filesystem directory entry normalnya tidak menghasilkan arbitrary slash dalam nama component.

Namun abstraction scanner tetap harus memastikan bahwa component tidak pernah diperlakukan sebagai:

.

atau

..

dalam context yang dapat mengubah root traversal.

Jika entry merupakan "." atau ".." secara eksplisit dari abstraction:

jangan recurse.

Symlink handling

Scanner harus menggunakan no-follow semantics.

Jika entry merupakan symlink:

scanner tidak boleh dereference secara default.

Ada beberapa pilihan policy:

skip symlink.

record symlink sebagai candidate yang ditolak policy.

record symlink untuk reporting.

Namun scanner tidak boleh mengikuti symlink menuju:

directory lain

filesystem lain

parent directory

outside trusted root.

Default yang disarankan:

symlink tidak direkursi.

Jika policy mengizinkan penghapusan symlink itu sendiri, symlink dapat menjadi candidate dengan ObjectType::Symlink.

Filesystem boundary

Scanner harus memastikan bahwa traversal tidak melewati filesystem boundary apabila target policy melarang cross-filesystem traversal.

Informasi minimal yang perlu diketahui:

device identity

filesystem identity jika tersedia

mount identity jika tersedia

Root identity

Jika child directory memiliki device berbeda:

jangan recurse jika cross-filesystem disabled.

Jika filesystem identity berubah secara unexpected:

scanner dapat menghasilkan Stale.

Jangan menganggap:

same path

berarti:

same filesystem.

Bind mount

Bind mount dapat membuat path terlihat berada di bawah target root tetapi sebenarnya menunjuk ke resource lain.

Scanner harus mempertimbangkan mount boundary.

Jika mount identity dapat dideteksi:

child mount dapat ditandai sebagai boundary.

Default conservative behavior:

jangan traverse ke mount lain kecuali target secara eksplisit mengizinkannya.

Jika implementation tidak dapat memastikan mount boundary:

policy harus mengambil conservative path.

Unknown lebih baik dianggap unsafe daripada otomatis allowed.

Object identity

Scanner membaca metadata candidate.

Identity minimal dapat meliputi:

device

inode

object type

metadata yang relevan

change indicator jika tersedia

Scanner menyimpan identity tersebut pada CandidateSnapshot.

Identity digunakan kemudian oleh Safety layer.

Scanner tidak boleh menganggap identity sebagai permanent lock.

Race:

scan

→ file diganti

→ execution

harus dianggap kondisi normal yang harus ditangani.

Directory replacement

Directory yang sedang discan dapat diganti atau dihapus.

Contoh:

scanner membuka directory A.

proses lain mengganti A.

scanner mencoba membaca child.

Scanner tidak boleh crash.

Possible result:

Stale

DirectoryGone

PermissionChanged

ReadError

Scanner harus membedakan error yang mengharuskan seluruh scan berhenti dari error pada satu subtree.

Partial scan

Satu subtree gagal dibaca.

Tidak selalu berarti seluruh job gagal.

ScanResult harus dapat merepresentasikan:

Completed

Partial

Cancelled

TimedOut

Stale

Failed

Jika policy mengizinkan partial discovery:

scanner dapat menghasilkan candidate dari subtree yang berhasil.

Namun report harus menyatakan bahwa scan tidak lengkap.

Jangan menghasilkan:

Completed

jika sebagian besar target tidak dapat diperiksa.

Scan budget

Scanner harus memiliki beberapa budget.

MaxEntries

MaxDepth

MaxMetadataReads

MaxDuration

MaxBytesInspected jika relevan

MaxDirectories

MaxCandidateCount jika diperlukan

Budget harus dicek selama traversal.

Jangan menunggu sampai akhir untuk memeriksa budget.

Entry budget

Setiap entry yang dibaca harus dihitung.

Contoh:

MaxEntries = 50000.

Setelah entry ke-50000:

scanner tidak boleh membaca entry ke-50001.

Hasil:

BudgetExceeded

atau PartialBudgetExceeded sesuai model result.

Depth budget

Depth mencegah directory tree yang sangat dalam menghabiskan resource.

Root depth:

0.

Child:

1.

Grandchild:

2.

Jika MaxDepth = 32:

depth 33 tidak boleh direkursi.

Depth bukan safety boundary untuk path escape.

RelativePath validation tetap wajib.

Metadata budget

Metadata read dapat lebih mahal daripada membaca directory entry.

Scanner harus memiliki MaxMetadataReads.

Jika budget habis:

candidate berikutnya tidak boleh diproses tanpa metadata jika metadata diperlukan untuk classification.

Scanner dapat:

skip

partial result

budget exceeded

sesuai contract.

Duration budget

Scanner harus menggunakan MonotonicClock.

Sebelum pekerjaan mahal:

check deadline.

Setelah batch:

check deadline.

Jangan hanya memeriksa timeout satu kali sebelum scan dimulai.

Cancellation

Cancellation token harus dicek secara berkala.

Minimal:

setiap batch directory entries

sebelum recurse

setelah metadata batch

ketika budget berubah

sebelum menghasilkan candidate batch

Cancellation tidak perlu diperiksa pada setiap CPU instruction.

Namun scanner tidak boleh terus melakukan pekerjaan lama setelah cancellation diterima.

Batch size

Scanner sebaiknya memproses entry dalam batch.

Tujuannya:

cancellation latency

fairness

budget accounting

memory bound

telemetry

Batch terlalu besar:

cancellation terlambat.

Batch terlalu kecil:

overhead tinggi.

Nilai batch harus configurable secara internal atau ditentukan implementation, bukan berasal langsung dari client.

Candidate streaming

Scanner tidak harus mengumpulkan seluruh candidate dalam memory.

Untuk target besar, gunakan streaming atau bounded collection.

Conceptual flow:

directory entry

→ classify

→ metadata

→ Candidate

→ bounded channel

→ Safety

Dengan demikian scanner tidak harus menyimpan jutaan candidate sekaligus.

Backpressure

Jika Safety consumer lebih lambat:

scanner harus berhenti atau memperlambat discovery.

Jangan membuat unbounded candidate queue.

Backpressure harus terintegrasi dengan cancellation.

Jika consumer gagal:

scanner harus menerima signal dan berhenti.

Candidate memory budget

Candidate harus memiliki bounded representation.

Jangan menyimpan:

arbitrary file content

entire directory data

unbounded metadata

file previews

file hashes untuk semua object

kecuali memang dibutuhkan policy.

Cleanup scanner bukan content scanner.

Metadata-first

Scanner sebaiknya menggunakan metadata yang paling murah untuk melakukan filtering awal.

Contoh:

file type

size

mtime

name

link count

identity

Kemudian hanya candidate potensial yang membutuhkan metadata tambahan.

Tujuannya mengurangi syscall dan I/O.

Age filtering

Minimum age dapat digunakan sebagai early filter jika metadata mtime tersedia.

Namun scanner harus berhati-hati terhadap clock.

Jika:

mtime > current_time

candidate jangan otomatis dianggap old.

Future timestamp dapat menghasilkan:

TooNew

InvalidTimestamp

atau ConservativeReject.

Clock anomaly

Filesystem timestamps dapat mengalami:

future time

zero timestamp

unexpected resolution

metadata corruption

Scanner tidak boleh crash.

Policy menentukan bagaimana timestamp abnormal diperlakukan.

Default conservative:

jangan hapus object dengan timestamp yang tidak dapat dipercaya.

Package scope

Untuk target per-package, scanner tidak boleh menganggap directory name sebagai PackageId tanpa validation.

Package identity harus berasal dari Target Catalog atau platform package mapping.

Path seperti:

com.example.app

tidak otomatis berarti PackageId valid.

User scope

Demikian juga directory user ID tidak boleh langsung dipercaya sebagai UserId hanya karena berada pada path tertentu.

Platform layer harus memberikan mapping.

Scanner hanya menggunakan scope yang sudah ditentukan catalog.

Excluded packages

ExcludedPackages harus diterapkan secara deterministic.

Jika PackageId termasuk exclusion:

scanner tidak boleh menghasilkan candidate dari target tersebut.

Namun exclusion tidak boleh dipakai sebagai security boundary terhadap arbitrary path.

Target Catalog tetap menjadi source of truth untuk target scope.

Hidden files

Hidden file bukan otomatis unsafe dan bukan otomatis removable.

Scanner boleh menemukan hidden files.

Policy yang menentukan apakah hidden file boleh menjadi candidate.

File type filtering

Scanner dapat melakukan initial object type classification.

Contoh:

RegularFile

Directory

Symlink

Socket

FIFO

Device

Unknown

ObjectType::Unknown harus diperlakukan conservative.

Jangan menganggap unknown sebagai regular file.

Special files

Device nodes, sockets, FIFO, dan special objects harus ditangani secara eksplisit.

Default:

special object tidak menjadi cleanup candidate.

Jika target tertentu memang membutuhkan operasi terhadap object khusus:

harus ada policy dan safety contract khusus.

Scanner tidak boleh memperluas scope sendiri.

Directory candidate

Directory tidak boleh langsung dianggap removable hanya karena kosong.

Scanner dapat menemukan empty directory.

Planner/policy menentukan apakah directory deletion diperbolehkan.

Safety harus tetap melakukan revalidation sebelum deletion.

Directory yang berubah dari empty menjadi non-empty:

execution harus menanganinya dengan aman.

Do not recursively delete

Scanner tidak boleh membuat semantics:

DeleteDirectoryRecursively

sebagai shortcut.

Recursive cleanup harus merupakan hasil eksplisit dari discovery terhadap child candidates.

Tujuannya agar setiap destructive operation tetap memiliki identity dan authorization.

Parent-child dependency

Jika file berada dalam directory yang juga candidate:

scheduler/planner harus menentukan ordering.

Contoh:

file candidate

directory candidate

Directory hanya boleh dihapus setelah child yang relevan sudah tidak ada.

Planner harus menghasilkan dependency order.

Scanner hanya melaporkan structure.

Duplicate candidate

Scanner dapat menemukan object yang tampak duplicate karena mount topology atau alias.

Candidate identity harus digunakan untuk deduplication bila diperlukan.

Path equality saja tidak selalu cukup.

Object identity juga tidak boleh digunakan sendirian tanpa mempertimbangkan target scope.

Deduplication key dapat berupa:

target

root identity

filesystem identity

object identity

relative path

sesuai kebutuhan.

Hard links

Dua path dapat menunjuk object yang sama melalui hard link.

Scanner boleh menghasilkan dua candidate path.

Safety/policy harus menentukan apakah menghapus satu path diperbolehkan.

Jangan menganggap dua path berarti dua object.

Jika operation semantics hanya unlink directory entry:

bytes affected tidak selalu sama dengan object storage reclaimed.

Telemetry harus membedakan logical deletion dan actual reclaimed storage jika dapat diketahui.

Race handling

Race adalah expected.

Scenario:

scanner membaca:

file A

inode 100

size 10MB

kemudian proses lain:

unlink A

buat file B

rename B menjadi A

Scanner tetap memiliki Candidate lama.

Safety layer harus melihat identity mismatch.

Expected result:

ChangedSinceScan

atau

AlreadyGone

Bukan:

delete new A

Hal ini adalah salah satu alasan scanner tidak boleh menghasilkan raw path authorization.

Rename race

File dapat berpindah nama setelah scan.

Jika executor hanya menggunakan relative path tanpa identity validation:

dapat menghapus object yang berbeda.

Karena itu final safety harus memverifikasi identity pada path saat execution.

Scanner membantu menyediakan expected identity.

Scanner dan Safety separation

Scanner:

menemukan.

Safety:

memverifikasi.

Scanner boleh berkata:

candidate ditemukan.

Scanner tidak boleh berkata:

candidate aman dihapus.

SafetyValidatedCandidate hanya dapat dibuat Safety layer.

Scanner output tidak boleh memiliki boolean:

safe_to_delete = true.

Candidate hanya berisi fakta.

Policy separation

Scanner juga tidak boleh menetapkan:

should_delete = true.

Policy melakukan decision.

Scanner dapat memberi:

mtime

size

type

target

package

user

relative path

identity

Policy memutuskan apakah data tersebut memenuhi rule.

Filesystem traversal API

Filesystem abstraction untuk scanner minimal membutuhkan:

open_root()

read_dir()

read_dir_entry()

stat_no_follow()

open_child_directory()

identity()

is_same_filesystem()

check_mount_boundary()

Semua API harus mengikuti ownership dan lifetime rules.

Scanner tidak boleh menggunakan raw libc call secara langsung jika architecture sudah menetapkan filesystem abstraction.

Raw syscall hanya berada pada low-level implementation.

Directory handle lifetime

Directory handle harus memiliki RAII/ownership semantics.

Ketika scanner selesai dengan directory:

handle ditutup.

Jika recursion menggunakan stack:

setiap directory handle harus memiliki owner.

Jangan menyimpan seluruh tree directory handles tanpa batas.

DFS atau BFS

Depth-first traversal memiliki keuntungan memory lebih kecil.

Breadth-first dapat berguna jika fairness atau shallow discovery lebih penting.

Versi pertama sebaiknya menggunakan bounded depth-first traversal dengan explicit stack.

Stack juga harus memiliki bound berdasarkan MaxDepth dan memory budget.

Recursive function call

Jangan menggunakan recursive Rust function tanpa memperhitungkan depth ekstrem.

Filesystem dapat memiliki tree sangat dalam.

Explicit stack lebih aman untuk bounded traversal.

Symlink race

Walaupun scanner tidak mengikuti symlink, object dapat berubah setelah metadata dibaca.

Contoh:

entry regular file.

metadata dibaca.

object diganti symlink.

Safety layer harus menggunakan no-follow semantics saat final validation.

Scanner tidak perlu mencoba menjamin filesystem tidak berubah.

Scanner hanya menyediakan snapshot.

Mount race

Mount dapat berubah setelah scanner melihat target.

Safety layer harus mendeteksi perubahan mount/filesystem identity.

Jika mount topology berubah:

job dapat menjadi Stale.

Jangan melanjutkan berdasarkan path lama.

User lock race

User dapat lock storage selama scan.

Scanner dapat kehilangan akses.

Expected result:

Deferred

Cancelled

Stale

atau Partial

sesuai platform semantics.

Tidak boleh memaksa membuka credential-encrypted storage.

Storage state adalah platform constraint, bukan sesuatu yang dapat di-bypass scanner.

SELinux

Scanner tidak boleh mencoba mengatasi denial dengan:

changing security context

disabling enforcement

running shell command

privileged workaround

SELinux denial adalah platform/security condition.

Scanner hanya melaporkan error.

Application/policy menentukan response.

Permission changes

Permission dapat berubah selama scan.

Jika directory menjadi unreadable:

scanner menghasilkan typed error/warning.

Jangan retry tanpa batas.

Retry harus dibatasi dan hanya untuk error yang memang transient.

Scan retry

Retry scan dapat dibuat jika:

storage transient unavailable

mount settling

Namun retry terhadap:

path escape

invalid entry

safety boundary violation

tidak berguna.

Kesimpulan

Scanner adalah discovery engine, bukan deletion engine.
