# 98.md — Final Architecture Invariants dan Production Readiness Gate

## Tujuan

Dokumen ini menjadi konsolidasi invariant yang harus tetap benar ketika seluruh rewrite selesai. Ia bukan daftar fitur, melainkan kontrak yang membatasi implementasi.

Architecture dianggap production-ready hanya jika invariant domain, safety, durability, lifecycle, resource, security, dan operational behavior dapat dibuktikan melalui code dan tests.

## 1. Domain Separation

```text
Target
Candidate
Policy
Plan
Authorization
Safety
Executor
Verifier
Recovery
```

Setiap konsep memiliki responsibility berbeda.

## 2. Target Invariant

Target menjelaskan object/resource yang tersedia dan trusted context-nya.

Raw path string tidak boleh otomatis menjadi Target authority.

## 3. Candidate Invariant

Candidate adalah observation dari scanner.

Candidate bukan authorization dan bukan bukti safety final.

## 4. Policy Invariant

Policy menjawab apakah operation diizinkan berdasarkan configured rules.

Policy tidak boleh menggantikan filesystem safety proof.

## 5. Plan Invariant

Plan immutable setelah authorization boundary kecuali explicit replan.

Plan memiliki identity/version/generation context.

## 6. Authorization Invariant

Authorization scoped terhadap operation/target/context.

Client tidak dapat memberikan authorization kepada dirinya sendiri.

## 7. Safety Invariant

Safety diverifikasi sedekat mungkin dengan mutation.

Safety failure berarti no mutation.

## 8. Executor Invariant

Executor adalah satu-satunya mutation boundary.

Scanner/planner/CLI tidak boleh melakukan destructive filesystem operation.

## 9. Verifier Invariant

Executor success belum sama dengan final success.

Verifier menentukan apakah postcondition terbukti.

## 10. Unknown Invariant

Unknown tidak sama dengan Failed.

Unknown tidak boleh di-retry secara blind.

## 11. Recovery Invariant

Recovery read-first dan idempotent.

Recovery tidak memperoleh authority baru hanya karena state lama unresolved.

## 12. Identity Invariant

JobId, AttemptId, OperationId memiliki semantics berbeda.

OperationId stabil lintas retry.

## 13. Idempotency Invariant

Duplicate request/event/publication tidak boleh menghasilkan duplicate logical mutation.

## 14. Durability Invariant

Destructive intent harus durable sebelum mutation dimulai.

## 15. Filesystem/DB Invariant

Database dan filesystem bukan satu transaction domain.

Jangan berpura-pura ada atomic transaction lintas keduanya.

## 16. Publication Invariant

External success/result publication dilakukan setelah durable state commit.

At-least-once publication harus aman melalui idempotency.

## 17. Resource Invariant

Setiap resource mempunyai owner dan lifetime.

RAII digunakan untuk process-local resource.

Durable ownership direcover setelah crash.

## 18. FD Invariant

FD adalah capability/resource, bukan safety proof dengan sendirinya.

Destructive path harus menggunakan correct descriptor-relative semantics.

## 19. Concurrency Invariant

Tidak ada dua active executor yang dapat melakukan conflicting mutation terhadap same logical operation/target tanpa explicit coordination.

## 20. Lock Invariant

Lock hierarchy deterministic.

Tidak menahan lock ketika melakukan indefinite/blocking wait.

## 21. Queue Invariant

Semua queue bounded.

Tidak ada input source yang dapat menghasilkan unbounded memory growth.

## 22. Event Invariant

Event adalah signal, bukan Job.

Event burst harus coalesced.

Authoritative state berasal dari snapshot/durable state.

## 23. Scheduler Invariant

Scheduler tidak melakukan filesystem mutation.

Scheduler hanya admission/coordination.

## 24. Idle Invariant

Tidak ada eligible work:

```text
no polling
no busy loop
no unnecessary wakelock
blocked wait
```

## 25. Android Lifecycle Invariant

Process death adalah normal failure mode.

Suspend/resume adalah lifecycle event, bukan correctness exception.

## 26. Power Invariant

Daemon tidak boleh mempertahankan device awake hanya untuk polling.

Wakeup harus mempunyai reason dan bounded work.

## 27. Configuration Invariant

Active configuration selalu valid.

Invalid reload tidak menggantikan valid config.

## 28. Generation Invariant

ConfigGeneration dan CatalogGeneration membentuk stale-context detection.

Plan yang stale harus revalidated/replanned.

## 29. Security Invariant

IPC untrusted.

No arbitrary shell command.

No self-reported caller authority.

## 30. Privilege Invariant

Privilege exposure seminimal mungkin.

Privileged helper menerima typed/scoped request, bukan arbitrary command.

## 31. Secret Invariant

Secret tidak boleh masuk ordinary logs, diagnostics, atau broad IPC response.

## 32. Migration Invariant

Schema migration tidak boleh menghasilkan state hybrid invalid.

Historical recovery evidence harus dipertahankan.

## 33. Upgrade Invariant

New binary harus melewati compatibility/migration/readiness gate sebelum mutation admission.

## 34. Rollback Invariant

Rollback tidak boleh mengasumsikan filesystem state dapat di-rollback hanya dengan database restore.

## 35. Performance Invariant

Performance optimization tidak boleh menghilangkan safety, authorization, verification, atau durability.

## 36. Capacity Invariant

Memory, FD, workers, queue, scan, dan operation size mempunyai explicit bound.

## 37. Observability Invariant

Setiap operation dapat dikorelasikan dan diagnosis tidak bergantung pada volatile logs saja.

## 38. Audit Invariant

Security/destructive action dapat ditelusuri tanpa menyimpan secret.

## 39. Error Invariant

Machine-readable error taxonomy membedakan:

```text
InvalidInput
Unauthorized
Unsafe
Conflict
Unavailable
Timeout
ResourceExhausted
PersistenceFailure
UnknownOutcome
```

## 40. Cancellation Invariant

Cancellation menghentikan future work sejauh possible, tetapi tidak mengubah unknown mutation outcome menjadi cancelled tanpa evidence.

## 41. Timeout Invariant

Timeout adalah control-flow event, bukan bukti bahwa filesystem mutation tidak terjadi.

## 42. Shutdown Invariant

Shutdown menghentikan admission, membangunkan blocked components, dan menyimpan state sebelum exit.

Correctness tidak bergantung pada graceful shutdown.

## 43. Startup Invariant

Startup order:

```text
store
→ migration
→ recovery
→ platform
→ scheduler
```

Normal mutation tidak dimulai sebelum recovery selesai.

## 44. Corruption Invariant

Corrupt durable state fail-closed terhadap destructive execution.

## 45. Testing Invariant

Critical invariants harus mempunyai tests, bukan hanya documentation.

## 46. Fault Injection Invariant

Crash/failure harus diuji pada mutation boundaries, persistence boundaries, lease transitions, queue overflow, dan lifecycle events.

## 47. Race Invariant

Concurrency tests harus mencakup:

- duplicate request
- stale worker
- target replacement
- config reload
- mount change
- cancellation/timeout race
- shutdown race

## 48. Production Gate

Release tidak boleh disebut production-ready hanya karena build/test happy path pass.

Minimum gate:

```text
architecture invariants pass
+ safety tests pass
+ recovery tests pass
+ lifecycle tests pass
+ security tests pass
+ resource bounds pass
+ power/idle tests pass
+ performance regression pass
+ migration/upgrade tests pass
```

## 49. Explicit Non-Goals

Architecture tidak menjanjikan:

- exactly-once distributed semantics
- atomic DB+filesystem transaction
- infinite queue
- guaranteed process survival
- guaranteed wake-from-suspend dari ordinary timer
- zero CPU under every external runtime/dependency condition

## 50. Final Definition of Done

Cache cleaner production-grade jika seluruh invariant di atas dapat dipetakan ke:

1. typed domain model
2. implementation module
3. durable state
4. test suite
5. operational diagnostic

Tidak boleh ada invariant penting yang hanya hidup di markdown.

## Final Gate Checklist

- [ ] Target/Candidate/Policy/Plan terpisah
- [ ] Typed IDs
- [ ] Explicit Job/Attempt/Operation state machine
- [ ] Target catalog + identity + generation
- [ ] Candidate scanner bounded
- [ ] Safety near mutation boundary
- [ ] Policy deterministic
- [ ] Planner immutable/deterministic
- [ ] Authorization scoped
- [ ] Executor single mutation boundary
- [ ] Verifier + reconciliation
- [ ] Durable Job/Operation store
- [ ] Crash-safe journal
- [ ] Idempotent retry/replay
- [ ] Resource ownership/recovery
- [ ] Bounded concurrency
- [ ] Bounded queues/backpressure
- [ ] IPC versioned/untrusted
- [ ] CLI contract stable
- [ ] Android adapter isolated
- [ ] Suspend/deep-sleep safe
- [ ] Security boundary tested
- [ ] Observability/audit tersedia
- [ ] Schema migration tested
- [ ] Config/policy migration tested
- [ ] Performance benchmarked
- [ ] Upgrade/rollback tested
- [ ] Fault injection tested
- [ ] Real-device lifecycle tested
- [ ] No hidden safety bypass

## Ultimate Invariants

1. Tidak ada destructive mutation tanpa Target + Policy + Plan + Authorization + Safety.
2. Executor adalah satu-satunya mutation boundary.
3. Destructive intent durable sebelum mutation.
4. Unknown selalu diperlakukan sebagai uncertainty.
5. Recovery tidak boleh blind retry.
6. OperationId stabil lintas retry.
7. DB dan filesystem diperlakukan sebagai consistency domain terpisah.
8. Publication terjadi setelah durable commit.
9. Semua queue/resource/concurrency bounded.
10. IPC/client tidak pernah menjadi authority.
11. Config/catalog generation melindungi terhadap stale context.
12. Process death dan suspend dianggap normal lifecycle condition.
13. Idle daemon tidak melakukan polling yang tidak perlu.
14. Safety/authorization tidak dapat dibypass oleh force flag.
15. Schema/upgrade/rollback tidak boleh merusak recovery evidence.
16. Security failure pada destructive path fail-closed.
17. Performance optimization tidak boleh mengorbankan correctness.
18. Observability membantu diagnosis tetapi bukan source of truth.
19. Setiap critical invariant harus dibuktikan oleh automated test.
20. Dokumentasi final harus dapat diterjemahkan menjadi dependency graph implementasi nyata.
