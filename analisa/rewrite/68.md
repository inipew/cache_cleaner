68.md — Target Catalog, Target Descriptor, Target Identity, Discovery, Mount Binding, Generation, Availability, Safety Classification, and Revalidation Contract

Tujuan

Dokumen ini mendefinisikan implementasi Target Catalog sebagai sumber kebenaran untuk seluruh target filesystem/cache yang dapat dipertimbangkan oleh cache_cleaner.

Rewrite tidak boleh lagi mengandalkan kumpulan hard-coded path yang tersebar di RuleEngine, scanner, cleaner, atau platform code.

Arsitektur target yang dituju:

Platform Adapter
      │
      ▼
Target Discovery
      │
      ▼
Target Descriptor
      │
      ▼
Target Catalog
      │
      ├── Scanner
      ├── Policy
      ├── Planner
      ├── Safety
      └── Executor

Target Catalog menjelaskan "apa targetnya".
Safety menjelaskan "apakah target/path aman disentuh sekarang".
Policy menjelaskan "apakah operation diizinkan secara policy".
Planner menentukan "operation apa yang akan dilakukan".
Executor melakukan mutation.

1. Target Bukan Raw Path

`/data/cache`, `/cache`, `/data/user/0/...` dan path lain tidak boleh menjadi identity target.

Path adalah location reference.

TargetId adalah identity.

2. TargetId

Setiap target mempunyai typed TargetId.

TargetId harus stabil sepanjang satu catalog generation.

3. TargetId Tidak Harus Persist Selamanya

Jika target identity bergantung pada filesystem/mount identity, TargetId dapat berubah setelah mount topology berubah.

Persisted reference harus menyimpan identity yang diperlukan untuk revalidation.

4. TargetDescriptor

Minimal descriptor:

```rust
pub struct TargetDescriptor {
    pub id: TargetId,
    pub kind: TargetKind,
    pub root: TrustedRoot,
    pub storage: StorageIdentity,
    pub safety_class: SafetyClass,
    pub capabilities: TargetCapabilities,
    pub availability: TargetAvailability,
    pub metadata: TargetMetadata,
}
```

5. TargetKind

Gunakan typed enum, bukan string bebas.

Contoh:

```rust
pub enum TargetKind {
    AndroidAppCache,
    AndroidCodeCache,
    AndroidExternalCache,
    SystemCache,
    DalvikCache,
    PackageData,
    UserData,
    Custom,
}
```

Final enum harus mengikuti target yang benar-benar didukung platform adapter.

6. Target Category != Target Instance

`AndroidAppCache` adalah kind.

`/data/user/0/com.example/cache` adalah instance/location.

7. Target Scope

Target harus mempunyai scope:

- system
- user
- package
- storage
- mount
- custom

Scope harus typed.

8. Package Binding

Jika target khusus package, descriptor dapat mempunyai typed PackageName.

PackageName tidak boleh menjadi arbitrary filesystem authority.

9. User Binding

Jika target user-specific, gunakan typed UserId.

10. StorageIdentity

Target filesystem harus dikaitkan dengan storage identity bila tersedia.

Minimal konsep:

- device major/minor
- filesystem identity
- mount identity
- mount point identity

11. Mount Identity

Mount point string saja tidak cukup sebagai identity.

Mount topology dapat berubah sementara path tetap sama.

12. Device Identity

Jika tersedia, simpan device identity untuk revalidation.

13. Filesystem Identity

Filesystem UUID atau equivalent identity dapat digunakan jika tersedia.

14. Root Identity

TrustedRoot harus mengikat path root dengan identity filesystem yang relevan.

15. TrustedRoot

TrustedRoot adalah boundary tempat relative target paths dapat di-resolve.

TrustedRoot bukan sekadar PathBuf.

16. Root Validation

Root harus diverifikasi sebelum dimasukkan ke catalog.

17. Root Availability

Target yang root-nya tidak tersedia tidak boleh dianggap executable hanya karena descriptor masih ada.

18. Availability

TargetAvailability minimal:

```rust
pub enum TargetAvailability {
    Available,
    TemporarilyUnavailable,
    PermissionDenied,
    MountMissing,
    IdentityChanged,
    Invalid,
}
```

19. Availability Is Snapshot

Availability adalah kondisi pada saat discovery/revalidation.

Bukan jaminan permanen sampai execution.

20. CatalogGeneration

Setiap snapshot catalog mempunyai typed CatalogGeneration.

Generation berubah ketika target topology/identity/descriptor yang relevan berubah.

21. Generation Monotonic

CatalogGeneration harus monotonically increasing dalam satu daemon lifecycle.

22. Generation != ConfigGeneration

ConfigGeneration mengidentifikasi configuration snapshot.

CatalogGeneration mengidentifikasi target topology snapshot.

23. Catalog Snapshot

Scanner/planner harus menerima immutable catalog snapshot.

24. No Mutable Catalog During Planning

Planner tidak boleh membaca descriptor yang berubah di tengah planning tanpa snapshot/version check.

25. Catalog Refresh

Refresh harus menghasilkan snapshot baru, bukan memodifikasi descriptor yang sedang digunakan secara in-place.

26. Atomic Catalog Swap

Current catalog dapat di-swap secara atomik setelah discovery dan validation selesai.

27. Failed Refresh

Jika discovery gagal, current valid catalog dipertahankan.

28. Partial Discovery

Partial discovery tidak boleh diam-diam menggantikan catalog lengkap.

Jika partial snapshot digunakan, statusnya harus explicit.

29. Discovery Error

Discovery error harus dibedakan dari "tidak ada target".

30. Empty Catalog

Empty catalog dapat valid jika memang tidak ada target, tetapi harus mempunyai provenance yang jelas.

31. Discovery Provenance

Catalog sebaiknya menyimpan:

- platform adapter version
- discovery timestamp
- discovery reason
- generation
- source capability

32. Discovery Source

Target discovery hanya boleh menggunakan capability platform yang tersedia.

33. Platform Adapter

Android-specific assumptions harus berada di platform adapter/target discovery, bukan generic planner.

34. Generic Core

Core engine tidak boleh mengetahui hard-coded `/data/user/0` jika informasi tersebut dapat diberikan descriptor.

35. Android Adapter

Android adapter bertanggung jawab memetakan:

- package paths
- user paths
- cache conventions
- system locations
- mount topology
- permissions/capabilities

36. OEM Variation

Target discovery harus mengantisipasi variasi OEM.

Hard-coded path yang tidak tervalidasi harus dianggap candidate discovery hint, bukan authority.

37. Discovery Hint

Static known path dapat digunakan untuk discovery, tetapi hasilnya harus melewati identity/safety validation.

38. No Path Guessing During Execution

Executor tidak boleh menemukan target baru dengan menebak path.

Executor hanya menerima TargetDescriptor/TargetId yang sudah divalidasi.

39. Custom Target

Custom target harus melalui validation yang sama seperti built-in target.

40. Custom Target Authority

Menambahkan custom target tidak boleh otomatis memberikan destructive permission.

41. SafetyClass

Target memiliki safety classification.

Contoh:

```rust
pub enum SafetyClass {
    EphemeralCache,
    UserData,
    SystemCritical,
    Protected,
    Custom,
}
```

42. SafetyClass Is Not Authorization

SafetyClass bukan izin untuk menghapus.

Ia adalah classification input bagi safety/policy.

43. Protected Target

Target system-critical/protected harus mempunyai invariant yang lebih ketat.

44. Protected Roots

Protected root tidak boleh menjadi destructive target kecuali policy domain secara eksplisit mendukung operation tersebut dan safety contract mengizinkannya.

45. TargetCapabilities

Descriptor dapat menyatakan capability seperti:

- Read
- Enumerate
- Delete
- Reclaim
- Metadata
- Verify

46. Capability Is Observed

Capability harus mencerminkan kemampuan platform yang benar-benar tersedia.

47. Capability Is Not Authorization

`Delete` capability berarti platform mampu melakukan delete.

Bukan berarti Job tertentu boleh delete.

48. Target Operation Matrix

Setiap TargetKind harus memiliki operation matrix.

Contoh:

| Target | Scan | Delete | Reclaim | Verify |
|---|---:|---:|---:|---:|
| AppCache | yes | policy | no | yes |
| SystemCritical | yes | no | no | yes |
| Custom | policy | policy | policy | policy |

49. Unsupported Operation

Planner harus menolak operation yang tidak didukung target capability.

50. Target Descriptor Immutability

Descriptor dalam snapshot harus immutable.

51. Identity Fields Immutable

TargetId, storage identity, root identity, dan kind tidak boleh berubah in-place.

52. Metadata Refresh

Metadata non-authoritative dapat diperbarui pada snapshot berikutnya.

53. Metadata != Identity

Display name, free space, human-readable label bukan identity.

54. Root Path Normalization

Root path harus dinormalisasi secara canonical sesuai safety contract.

55. Relative Target Path

Candidate path harus disimpan relatif terhadap TrustedRoot jika target bersifat rooted.

56. Absolute Path Boundary

Absolute path tidak boleh digunakan sebagai substitute untuk trusted root resolution.

57. Symlink Root

Root yang merupakan symlink harus ditangani secara explicit dan tidak boleh diterima sebagai trusted root tanpa verification.

58. Symlink Inside Target

Symlink traversal harus mengikuti safety rules, bukan filesystem default behavior secara blind.

59. Mount Boundary

Target descriptor dapat menetapkan apakah traversal harus berhenti pada mount/filesystem boundary.

60. Cross-Mount Traversal

Default harus menolak cross-mount traversal untuk target yang scoped ke satu filesystem.

61. Bind Mount

Bind mount dapat membuat path topology berbeda dari asumsi lexical path.

Target identity harus direvalidasi berdasarkan filesystem/mount information.

62. Overlay Filesystem

Overlay/union filesystem harus dianggap special case.

Safety tidak boleh hanya mengandalkan device number sederhana jika platform semantics lebih kompleks.

63. FUSE

FUSE target harus diidentifikasi sebagai filesystem capability khusus jika relevant.

64. Network Filesystem

Network filesystem harus mempunyai explicit capability/policy classification sebelum destructive operation.

65. Read-Only Mount

Read-only mount harus menghasilkan unavailable-for-mutation capability.

66. Permission Changes

Permission yang berubah setelah discovery membuat capability snapshot stale.

67. Revalidation

Sebelum mutation, target harus direvalidasi.

68. Revalidation Inputs

Minimal:

- target identity
- root identity
- mount identity
- storage identity
- availability
- required capability

69. Revalidation Failure

Jika identity berubah:

operation harus stale/blocked.

Jangan mengarahkan operation ke target baru hanya karena path sama.

70. TOCTOU

Catalog discovery adalah snapshot, bukan jaminan execution safety.

Safety Gate harus melakukan final validation setelah planning/authorization dan sebelum mutation.

71. Target Generation Binding

Plan menyimpan CatalogGeneration.

72. Authorization Generation Binding

Authorization menyimpan CatalogGeneration yang menjadi dasar keputusan.

73. Execution Generation Check

Executor harus memastikan catalog generation masih valid atau target identity tetap terbukti equivalent.

74. Equivalent Target

Jika CatalogGeneration berubah, operation hanya dapat dilanjutkan jika target identity revalidation membuktikan equivalence sesuai policy.

75. No Generation Bypass

`force=true` tidak boleh mengabaikan generation mismatch.

76. Target Rename

Rename mount point tidak boleh dianggap target baru atau sama secara otomatis.

Identity harus diverifikasi.

77. Target Disappearance

Target yang hilang setelah planning harus menghasilkan stale/unavailable result.

78. Target Reappearance

Target yang muncul kembali tidak otomatis dianggap target lama.

Identity harus cocok.

79. Device Reuse

Device number yang sama tidak selalu cukup untuk membuktikan identity sama.

80. Inode Root Identity

Root inode/device dapat menjadi bagian identity snapshot tetapi harus dipakai sesuai filesystem semantics.

81. Root Replacement

Jika root directory dihapus/recreated, identity change harus terdeteksi jika observable.

82. Package Reinstall

Package cache target setelah uninstall/reinstall tidak boleh diasumsikan sama hanya karena package name sama.

83. Package UID Change

Package identity harus mempertimbangkan UID/user identity jika relevant.

84. User Boundary

Target user A tidak boleh tertukar dengan target user B hanya karena relative package path sama.

85. Package Boundary

Operation terhadap package cache harus tetap berada dalam package target scope.

86. Catalog Filtering

Caller dapat meminta target kind/scope tertentu.

Filtering tidak boleh menghapus safety metadata.

87. Catalog Query

Query API harus mengembalikan immutable descriptors.

88. No Mutable Handle Exposure

Catalog tidak boleh memberikan mutable reference yang memungkinkan caller mengubah descriptor.

89. Target Lookup

Lookup by TargetId harus gagal jika generation/identity mismatch bila caller meminta generation-bound lookup.

90. Snapshot API

Recommended:

```rust
pub struct TargetCatalogSnapshot {
    pub generation: CatalogGeneration,
    pub targets: Arc<[TargetDescriptor]>,
}
```

91. Catalog Authority

Hanya Catalog Manager/Discovery layer yang boleh membuat TargetDescriptor authoritative.

92. Scanner Authority

Scanner boleh menghasilkan Candidate dari TargetDescriptor.

Scanner tidak boleh mengubah TargetDescriptor.

93. Planner Authority

Planner memilih target dari catalog snapshot.

Planner tidak membuat target baru.

94. Policy Authority

Policy menilai target berdasarkan descriptor/classification.

95. Safety Authority

Safety melakukan runtime identity/path validation.

96. Executor Authority

Executor menggunakan resolved target context yang diberikan.

97. Target Descriptor Serialization

Persistence/IPC harus menggunakan DTO versioned.

Jangan serialize internal file descriptors/OS handles sebagai target identity.

98. Persisted Target Reference

Persisted job hanya boleh menyimpan reference yang dapat direvalidasi.

Minimal:

- TargetId
- kind
- root identity/reference
- storage identity
- catalog generation

99. Stale Persisted Target

Jika persisted target tidak lagi cocok dengan current topology, Job harus stale/recovery, bukan diarahkan ke target lain.

100. Catalog Recovery

Pada daemon restart, catalog generation dapat dimulai ulang dengan epoch baru atau monotonic persisted generation.

Implementation harus memastikan stale references tidak accidentally cocok.

101. Generation Epoch

Recommended untuk persisted systems:

CatalogGeneration = (epoch, sequence)

atau opaque generation yang tidak reuse.

102. Generation Reuse

Jangan menggunakan integer kecil yang dapat wrap-around dan kembali ke generation lama.

103. Overflow

Generation arithmetic harus checked/saturating sesuai domain; overflow harus menghasilkan explicit failure.

104. Catalog Refresh Triggers

Refresh dapat dipicu oleh:

- startup
- mount change
- package install/uninstall
- user lifecycle change
- configuration change yang memengaruhi target discovery
- periodic reconciliation
- explicit admin request

105. Event-driven Refresh

Platform event dapat menjadi hint untuk refresh.

Event tidak boleh dianggap authoritative tanpa re-discovery.

106. Periodic Reconciliation

Event loss harus ditutup dengan periodic catalog reconciliation.

107. Debounce

Burst event tidak boleh menyebabkan discovery storm.

108. Refresh Serialization

Concurrent refresh harus dikontrol.

Gunakan single-flight atau generation-aware replacement.

109. Stale Refresh

Refresh result yang lebih tua tidak boleh overwrite catalog yang lebih baru.

110. Discovery Timeout

Discovery harus mempunyai bounded timeout jika source dapat hang.

111. Discovery Resource Limits

Target count, package count, path length, metadata size, dan traversal depth harus bounded.

112. Target Explosion

Sistem harus mencegah malformed/custom input menghasilkan jutaan descriptor tanpa limit.

113. Duplicate Targets

Discovery duplicate harus dideduplicate berdasarkan identity yang tepat, bukan display path saja.

114. Conflicting Descriptors

Jika dua discovery source menghasilkan descriptor dengan identity sama tetapi metadata safety berbeda, conflict harus explicit dan tidak boleh memilih salah satu secara arbitrary.

115. Conservative Conflict Resolution

Conflict safety classification harus memilih hasil paling restrictive atau menandai target invalid, sesuai policy yang terdokumentasi.

116. Target Ordering

Catalog ordering harus deterministic untuk planning/reproducibility.

117. Target Priority

Priority dapat digunakan untuk scheduling/planning tetapi tidak boleh mengubah safety classification.

118. Display Metadata

Human-readable name boleh disediakan untuk UI.

Tidak boleh dipakai sebagai authority.

119. Target Documentation

Setiap built-in TargetKind harus memiliki dokumentasi:

- intended scope
- root derivation
- expected filesystem
- allowed operations
- protected invariants
- verification strategy

120. Implementation Mapping

Migrasi dari code saat ini harus memindahkan hard-coded Android/OEM roots dari RuleEngine menjadi discovery descriptors.

RuleEngine lama tidak boleh menjadi source of truth setelah TargetCatalog aktif.

121. Compatibility Layer

Selama migrasi, legacy path rules dapat menjadi discovery adapter sementara.

Compatibility layer harus jelas diberi status deprecated.

122. No Dual Authority

Tidak boleh ada kondisi dimana TargetCatalog mengatakan target aman tetapi legacy RuleEngine secara independen menganggap path berbeda sebagai target authority.

123. Cutover

Setelah TargetCatalog menjadi authoritative, legacy target lists harus dihapus atau hanya digunakan sebagai non-authoritative hints.

124. Target Test Fixtures

Setiap target kind harus mempunyai fixture untuk:

- normal mount
- missing root
- read-only
- wrong filesystem
- symlink root
- replacement root
- cross-mount
- permission denied
- identity mismatch

125. Fuzzing

Target discovery/parser harus difuzz dengan malformed package names, paths, mount records, dan custom target definitions.

126. Property

Property utama:

Tidak ada TargetDescriptor yang masuk catalog sebagai executable target tanpa melewati validation.

127. Safety Property

Target identity mismatch tidak pernah menghasilkan executable mutation context.

128. Generation Property

Stale CatalogGeneration tidak boleh memperluas authority.

129. Scope Property

Target scope tidak boleh berubah karena filtering atau serialization.

130. Capability Property

Capability platform tidak boleh berubah menjadi authorization secara implicit.

131. Restart Property

Catalog setelah restart tidak boleh menganggap persisted TargetId valid tanpa revalidation.

132. Determinism Property

Input discovery yang sama harus menghasilkan descriptor ordering dan identity yang sama, kecuali metadata runtime yang memang berubah.

133. Atomicity Property

Observer hanya boleh melihat old valid catalog atau new valid catalog, bukan partial catalog.

134. Failure Property

Discovery failure mempertahankan last known valid catalog jika aman dilakukan.

135. Availability Property

Unavailable target tidak boleh diberikan mutation capability.

136. Read-only Property

Read-only storage tidak boleh menghasilkan Delete capability.

137. Protected Property

Protected target tidak boleh menjadi executable destructive target hanya karena caller memiliki generic delete capability.

138. Definition of Done

Target Catalog dianggap production-ready jika:

- semua target mempunyai TargetId typed
- TargetDescriptor immutable
- TrustedRoot tervalidasi
- storage/mount identity tersedia bila platform mendukung
- discovery terisolasi di platform adapter
- hard-coded path bukan lagi mutation authority
- CatalogGeneration tersedia
- refresh atomic
- failed refresh tidak merusak catalog valid
- stale refresh tidak dapat overwrite snapshot baru
- availability explicit
- capability != authorization
- safety classification explicit
- target scope explicit
- package/user binding typed
- final revalidation tersedia
- generation mismatch aman
- cross-mount behavior explicit
- symlink behavior explicit
- duplicate/conflict behavior deterministic
- resource limits diterapkan
- crash/restart revalidation diuji
- fuzz/property tests tersedia

139. Final Invariants

1. TargetId adalah identity, bukan path string.
2. TargetDescriptor immutable dalam snapshot.
3. TrustedRoot adalah security boundary.
4. Path discovery bukan authorization.
5. CatalogGeneration mengikat snapshot target topology.
6. ConfigGeneration dan CatalogGeneration tidak boleh dicampur.
7. Availability adalah snapshot, bukan jaminan execution.
8. Capability bukan authorization.
9. SafetyClass bukan authorization.
10. Executor tidak boleh menemukan target baru dengan path guessing.
11. Target identity harus direvalidasi sebelum mutation.
12. Identity mismatch selalu fail-safe.
13. Stale catalog tidak boleh menghasilkan mutation.
14. Target disappearance tidak boleh diarahkan ke target lain.
15. Target reappearance harus identity-checked.
16. Read-only mount tidak mempunyai mutation capability.
17. Protected target mempunyai invariant tambahan.
18. Package/user scope tidak boleh bocor.
19. Discovery failure tidak boleh mengganti valid catalog dengan partial unknown state.
20. Concurrent refresh tidak boleh menghasilkan stale overwrite.
21. Duplicate target harus deterministic.
22. Conflicting safety metadata tidak boleh diselesaikan secara permissive.
23. Persisted target reference harus dapat direvalidasi.
24. Restart tidak boleh blind-trust TargetId lama.
25. Hard-coded path hanya boleh menjadi discovery hint/compatibility layer.
26. Tidak boleh ada dual target authority setelah cutover.
27. Target Catalog harus dapat diaudit berdasarkan generation dan provenance.
28. Semua destructive operation harus melewati TargetCatalog + Safety Gate sebelum Executor.
