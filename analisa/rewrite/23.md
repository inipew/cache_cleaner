Lanjut ke **`planner/`**. Ini layer yang mengubah keputusan policy menjadi **rencana operasi yang eksplisit dan immutable**.

Prinsipnya:

> **Planner menentukan WHAT akan dilakukan, tetapi tidak melakukan apa pun.**

Jadi setelah Planner selesai, Executor tidak perlu “berpikir” lagi.

Karena Executor kemudian harus memutuskan:

```text id="q8v3m1"

directory?
recursive?

mount?
```

Itu mengembalikan decision-making ke destructive layer.

Dengan typed operation:

```text id="m2r7x9"

```

semantics sudah final.

# 381. `RemoveEmptyDirectory`

```rust id="k9r2x6"

    target: DirectoryTarget,
}
```

Dengan:

```rust id="m3q7p1"

    pub identity: ObjectIdentity,

```

---

# 382. Ini sangat penting

Planner tidak boleh menghasilkan:

```text id="x7m2q8"
RemoveDirectory("/cache/old")
```

yang kemudian Executor berkata:

> “Kalau tidak kosong, saya hapus semua.”

Tidak.

`RemoveEmptyDirectory` berarti tepat:

> hapus directory **hanya jika kosong**.

Kalau tidak kosong:

```text id="p5n8r3"
ENOTEMPTY
```

→ failure/skipped.

---

# 383. Recursive delete

Untuk v1:

> **Jangan expose `RemoveTree` sebagai operation publik.**

Karena recursive deletion memperbesar attack surface.

Lebih aman menghasilkan:

```text id="q2m7x4"
RemoveFile(a)
RemoveFile(b)
RemoveFile(c)
RemoveEmptyDirectory(parent)
```

Planner mengetahui seluruh scope.

---

# 384. Keuntungan individual operations

Plan bisa terlihat:

```text id="r8p3m1"
1. RemoveFile old/a
2. RemoveFile old/b
3. RemoveEmptyDirectory old
```

Executor tidak punya hak untuk membuat:

```text id="x6q1n9"
4. RemoveFile old/c
```

sendiri.

---

# 385. Executor tidak boleh memperluas scope

Ini invariant:

```text id="m4q8v2"
Executor may execute planned operations.
Executor may not discover additional deletion targets.
```

Jadi kalau:

```text id="k3p7m1"
old/
  a
  b
  unexpected-c
```

plan hanya:

```text id="n8x2q5"
delete a
delete b
delete old if empty
```

`unexpected-c` tetap ada.

---

# 386. Dependency

Untuk:

```text id="q5m8r1"
old/a
old/b
old/
```

dependency:

```text id="x7p2n9"
a ─┐
   ├──> remove old
b ─┘
```

Parent directory hanya boleh dihapus setelah children selesai.

# 389. Cycle detection

Bug:

```text id="k6r2m8"
A depends on B
B depends on A
```

tidak boleh masuk Executor.

`validate_plan()` harus menolak cycle.

Algoritma sederhana:

```text id="p7n3x1"

```

tidak perlu graph framework.

# 390. Ordering

Topological order:

```text id="m4q8r2"
children
   ↓
empty parent dirs
   ↓
maintenance
```

Contoh:

```text id="x8p1n6"
RemoveFile(old/a)
RemoveFile(old/b)
RemoveEmptyDirectory(old)

```

# 391. Mengapa Trim setelah deletion?

Karena:

```text id="q3m7x9"
delete
  ↓
filesystem state updated
  ↓
verification
  ↓
trim
```

TRIM adalah maintenance operation, bukan deletion prerequisite.

Dan TRIM sendiri sebaiknya hanya dijalankan jika policy/config mengizinkan.

---

# 392. F2FS maintenance

Urutan yang lebih aman:

```text id="v5n2q8"
filesystem cleanup
    ↓
verify cleanup
    ↓
F2FS maintenance
```

Jika F2FS operation gagal:

```text id="m1x7p4"
file cleanup tetap berhasil
```

Job dapat:

```text id="q8r3n6"
CompletedWithWarnings
```

# 393. ZRAM terpisah

ZRAM jangan dianggap bagian normal:

```text id="x4p9m2"

```

ZRAM operation harus explicit:

```text id="n7q3v8"
Maintenance::Zram(...)
```

dan memerlukan authorization/policy sendiri.

# 394. Dedup

Ada kemungkinan Scanner menghasilkan candidate yang sama karena:

```text id="m5r8q1"
overlapping target roots
```

atau bug catalog.

Planner harus punya defense:

```text id="p2x7n4"
deduplicate by object identity + target scope
```

---

# 395. Jangan dedup inode secara global tanpa konteks

Misalnya:

```text id="q8m3v1"
(dev=42, inode=100)
```

muncul dalam dua target.

Belum tentu dua operation identik secara semantic.

Jadi key lebih aman:

```text id="x6r2p9"
(TargetId, ObjectIdentity)
```

Jika target semantics berbeda, path identity juga dapat dipertimbangkan.

# 396. Hard links

Contoh:



Keduanya valid karena yang dihapus adalah dua directory entries.

Tetapi estimate:

# 408. Mengapa immutable?

Karena kita ingin:

```text id="r9m2p5"
Plan validated
     ↓
Authorization
     ↓
Execution
```

Jika plan bisa dimodifikasi di tengah:

```text id="q7x4n1"

      ↓
operation changed
      ↓
executor
```

maka authorization menjadi meaningless.

# 411. Conflict detection

Contoh invalid:


# 412. Parent/child conflict

Misalnya:

```text id="n4q7m1"
RemoveEmptyDirectory(old)
```

tetapi child:

```text id="p8x3r6"
old/a
```

tidak ada operation untuk remove `a`.

Plan sebenarnya mungkin valid jika directory memang sudah kosong pada execution time.

Tetapi kalau scanner melihat `a` dan policy menolak `a`, maka parent removal:

```text id="m2k9q5"
should not be planned
```

kecuali Planner memiliki alasan eksplisit bahwa `a` tidak akan menghalangi.

Untuk v1, aturan sederhana:

> **Directory removal hanya direncanakan jika semua known children yang diperlukan untuk empty state juga ada dalam plan, atau scanner membuktikan directory kosong.**

Ini menghindari false expectation.

---

# 413. Empty directory candidate

Scanner dapat membedakan:

```text id="q7n3x8"
DirectoryCandidate {
    identity,
    child_count,
}
```

Jika:

```text id="m5p2r9"
child_count == 0
```

Planner dapat menghasilkan:

```text id="x8q4m1"
RemoveEmptyDirectory
```

Jika tidak kosong:

```text id="n3r7k2"
```

jangan menghasilkan directory removal kecuali semua children memang planned for deletion.

# 414. Jangan delete root

Planner harus memiliki hard validation:

```text id="p6m1x8"
relative_path.is_empty()
```

→ reject `RemoveEmptyDirectory`.

Root deletion tidak pernah valid.

Ini defense kedua setelah Scanner.

# 421. Contoh nyata

Filesystem:

```text id="x4p7m2"
cache/
├── old-a.bin       100 MB
├── old-b.bin        50 MB
├── recent.bin       20 MB
└── old-dir/
    └── old-c.bin    30 MB
```

Policy:

```text id="n8q3m1"
old-a → Allow
old-b → Allow
recent → Reject(TooYoung)
old-c → Allow
```

Planner menghasilkan:

```text id="r5m2x8"
Plan #42

1. RemoveFile old-a.bin
2. RemoveFile old-b.bin
3. RemoveFile old-dir/old-c.bin
4. RemoveEmptyDirectory old-dir
```

Summary:

```text id="q7p1n4"
operations = 4
files = 3
directories = 1
estimated logical bytes = 180 MB
```

Executor **hanya** boleh menjalankan empat operation itu.

# 422. Dan jika filesystem berubah?

Misalnya sebelum Executor:

```text id="m3x8q2"
old-a.bin → replaced
```

Executor:

```text id="p7n4r1"
identity mismatch
```

→ operation gagal/skip.

Executor **tidak** membuat plan baru:

```text id="x5q2m8"
"there is another old file, delete that instead"
```

Itu tanggung jawab pipeline baru:

```text id="n8r3p6"
scan → safety → policy → planner
```

```text
                    ┌────────────┐
                    │  Platform  │
                    └─────┬──────┘
                          ▼
                    Target Catalog
                          │
                          ▼
                       Scanner
                          │
                          ▼
                      Candidate
                          │
                          ▼
                        Safety
                          │
                          ▼
                  SafetyValidated
                          │
                          ▼
                       Policy
                          │
                          ▼
                   PolicyApproval
                          │
                          ▼
                       Planner
                          │
                          ▼

                          │
                          ▼
                    Authorization
                          │
                          ▼
                   AuthorizedPlan
                          │
```

**Tahap berikutnya adalah `authorization/` + IPC security boundary.**

Di sana kita perlu menghubungkan `SO_PEERCRED`, `uid/gid/pid`, role **Root/System/Shell**, capability seperti `StartCleanup`, `DeepCleanup`, `Trim`, `ZramMaintenance`, `ReloadConfig`, dan `StopDaemon` ke `AuthorizedPlan`—dengan aturan penting bahwa **bahkan Root tidak pernah mendapatkan capability untuk bypass Safety atau membuat arbitrary filesystem operation**.
