74.md — Executor, Mutation Boundary, Operation Execution, Cancellation, Resource Ownership, Retry, Unknown Outcome, Verification Handoff, and Recovery Contract

Tujuan

Executor adalah satu-satunya layer yang boleh melakukan filesystem mutation untuk cleanup operation yang telah melewati Planner, Authorization, ResourceManager, dan final SafetyGate.

Pipeline:

Plan → Authorization → Resource Admission → SafetyProof → Executor → Verifier → Reconciler

1. Single Mutation Boundary

Seluruh destructive filesystem syscall harus dapat ditelusuri ke Executor.

2. No Bypass

Tidak boleh ada cleaner/helper/CLI/platform function yang dapat melakukan destructive mutation tanpa execution context.

3. Typed Operation

Executor menerima PlannedOperation, bukan arbitrary path/command string.

4. Authorized Context

Executor membutuhkan AuthorizedExecutionContext.

5. SafetyProof

Executor mutation API membutuhkan SafetyProof yang sesuai OperationId.

6. Proof Consumption

SafetyProof harus dikonsumsi/diperiksa tepat sebelum mutation.

7. No Boolean Gate

Jangan expose `delete(path, authorized: bool)`.

8. No Shell

Executor tidak boleh mengubah candidate path menjadi shell command.

9. Syscall-Level

Gunakan typed filesystem/platform APIs.

10. Operation Kind

Dispatch berdasarkan enum OperationKind, bukan string command.

11. Delete File

DeleteFile harus menggunakan identity-bound resolution dan no-follow semantics sesuai platform.

12. Delete Directory

DeleteDirectory harus mempunyai explicit recursive semantics.

13. Recursive Delete

Recursive deletion harus bounded by depth/object/byte/resource budgets.

14. Child Ordering

Untuk directory removal, children harus selesai sebelum parent bila required.

15. Symlink

Executor default menolak destructive symlink target.

16. Special File

Special files tidak boleh dihapus oleh generic file cleanup kecuali operation kind explicit mendukungnya.

17. Cross Mount

Executor harus enforce mount boundary requirement dari operation/safety proof.

18. Read-only

Mutation pada read-only filesystem harus gagal.

19. Identity Revalidation

Executor tidak boleh mengandalkan metadata dari scan saja.

20. Final Resolution

Object harus di-resolve lagi menggunakan TrustedRoot/safe descriptor.

21. Identity Match

Resolved object harus match expected Candidate observation sesuai Safety contract.

22. Replacement

Path same + object different = stale/blocked.

23. Missing Object

Missing object harus diklasifikasikan oleh Verifier/Reconciler, bukan otomatis success.

24. Atomic Mutation

Gunakan atomic OS primitive jika operation semantics membutuhkan atomicity.

25. Rename

If rename is supported, use same safety principles for source/destination.

26. Temporary Files

Temporary executor state harus berada di controlled location dan mempunyai cleanup strategy.

27. FD Ownership

Executor harus jelas memiliki borrowed/owned descriptors.

28. FD Lifetime

Directory/root FD harus hidup selama resolution/mutation sequence yang membutuhkannya.

29. FD Reuse

Tidak boleh memakai closed integer FD sebagai identity.

30. Close-on-exec

Set CLOEXEC jika subprocess dapat dibuat.

31. No Ambient Authority

Executor tidak boleh mencari arbitrary global root berdasarkan environment variable tanpa validation.

32. Platform Adapter

OS-specific syscalls berada pada filesystem/platform adapter.

33. Generic Executor

Generic executor orchestrates operation; adapter performs platform-specific primitive.

34. Android

Android adapter harus menangani kernel/API variation secara explicit.

35. Permission Error

Permission failure menjadi structured ExecutionError.

36. Not Found

ENOENT dibedakan dari other IO errors.

37. Read-only Error

EROFS harus mapped secara explicit.

38. Busy

EBUSY harus explicit dan tidak otomatis retry tanpa policy.

39. Interrupted

EINTR dapat retry pada syscall tertentu sesuai safe platform semantics.

40. Retry Policy

Retry hanya untuk error yang diklasifikasikan transient.

41. Retry Count

Retries bounded.

42. Retry Backoff

Backoff bounded dan cancellation-aware.

43. No Retry Identity Mismatch

Identity mismatch tidak boleh di-retry sebagai blind path operation.

44. No Retry Permission

Permission denial tidak boleh infinite retry.

45. No Retry Read-only

Read-only tidak boleh diulang tanpa environment change/reconciliation.

46. AttemptId

Setiap execution attempt mempunyai AttemptId baru.

47. OperationId Stable

Retry mempertahankan OperationId/logical identity.

48. Attempt Persistence

Attempt state harus durable sebelum mutation jika crash recovery membutuhkan classification.

49. Execution Journal

Record meaningful boundaries:

- admitted
- safety passed
- syscall started
- syscall returned
- verification requested

50. Syscall Started

Catatan syscall start penting untuk unknown-outcome recovery.

51. Unknown Outcome

Jika process crash atau timeout pada window mutation, result harus `Unknown`, bukan Failed/Success tanpa reconciliation.

52. Timeout

Timeout saat sebelum syscall = no mutation.

Timeout saat syscall = potentially unknown.

53. Cancellation

Cancellation sebelum syscall dapat stop execution.

54. Cancellation During Syscall

Cannot guarantee cancellation of kernel syscall; result must reconcile.

55. Cancellation After Mutation

Mutation result remains real; cancellation affects subsequent work, not history.

56. Cooperative Cancellation

Check cancellation between operations and batches.

57. No Rollback Assumption

Filesystem delete tidak diasumsikan rollbackable.

58. Partial Job

Executor harus mendukung partial completion.

59. Dependency

Executor hanya menjalankan operation ketika dependencies satisfied.

60. Dependency Failure

Blocked dependents harus explicit.

61. Resource Reservation

Executor tidak boleh mutate tanpa required resource reservation.

62. Reservation Identity

Execution context harus bind ReservationId jika resource manager memerlukannya.

63. Reservation Lifetime

Reservation harus mencakup mutation critical section.

64. Lock Ownership

Executor hanya memegang lock sesuai scope operation.

65. Lock Ordering

Multi-lock operation mengikuti deterministic ordering.

66. Deadlock

Avoid lock acquisition cycles.

67. Concurrency

Independent operations dapat parallelize.

68. Same Target

Operations pada same target/root harus mengikuti conflict/lock semantics.

69. Same Object

Duplicate object mutation harus deduplicate atau serialize safely.

70. Resource Pressure

Jika ResourceManager preempts execution sebelum mutation, operation can pause safely.

71. Preemption

Preemption harus terjadi pada safe checkpoint, bukan memaksa interrupt unsafe syscall.

72. Memory

Recursive cleanup harus bounded memory.

73. Open Handles

Number of open FDs harus bounded.

74. Batch Size

Batch mutation harus bounded.

75. Progress

Progress harus berbasis actual completed operations/bytes, bukan planned total saja.

76. Unknown Progress

Unknown mutation outcome tidak boleh menghitung object sebagai deleted sampai verifier/reconciliation memastikan.

77. Accounting

Bytes freed hanya diakui setelah verification/accounting contract.

78. Free Space

Filesystem free-space delta bukan sole proof bahwa specific delete succeeded.

79. Metrics

Record operation latency, syscall errors, retries, bytes, objects, unknown outcomes.

80. Privacy

Path logs harus redacted sesuai policy.

81. Audit

Record OperationId, AttemptId, AuthorizationId, TargetId, generations, result code.

82. No Secret Logging

Never log credentials or privileged tokens.

83. Error Context

ExecutionError harus structured dan include safe contextual identifiers.

84. Panic

Executor panic harus ditangkap pada worker boundary dan recovery dijalankan.

85. Worker Crash

Job/operation remains non-terminal until recovery reconciles it.

86. Restart

On restart, operations in Executing/Verifying/Unknown must be reconciled.

87. Blind Resume

Never blindly rerun an unknown mutation.

88. Reconciliation

Reconciler menentukan actual state dari filesystem/object identity.

89. Idempotent Rerun

Rerun only after reconciliation proves safe.

90. Verification Handoff

Successful syscall does not necessarily equal verified operation success.

91. Verifier Input

Pass operation identity, expected postcondition, and relevant before-state.

92. Postcondition

Example DeleteFile postcondition: expected object identity is absent.

93. Directory Postcondition

Directory deletion requires absence/expected subtree semantics.

94. Verification Failure

Verification failure is distinct from syscall failure.

95. Verification Unknown

Unable to verify must be Unknown/RecoveryRequired, not success.

96. Operation Result

Executor result should be provisional until Verifier confirms final state.

97. Terminal State

Executor does not directly mark Job Completed; it reports execution outcome to state machine/verifier.

98. Job State Ownership

Only lifecycle coordinator/state machine changes Job state.

99. Operation State Ownership

OperationStore/state machine owns durable operation status.

100. Executor Statelessness

Avoid storing authoritative lifecycle state only in in-memory Executor.

101. Idempotency Key

Mutation request should have stable OperationId/logical key.

102. Duplicate Execution

Duplicate executor request must be detected before mutation or reconciled.

103. Double Delete

Repeated delete should be safe only under defined identity semantics.

104. Path Reuse

A second request must not delete replacement object simply because original path was deleted.

105. Safety Recheck

Every retry that can mutate must obtain/revalidate safety context.

106. Authorization Recheck

Retry after expiry/revocation requires fresh authorization.

107. Generation Recheck

Retry after catalog/config change must check generation compatibility.

108. Deadline

Execution context deadline must be enforced.

109. Expired Operation

Expired operation cannot start a new mutation attempt.

110. Shutdown

Shutdown barrier prevents new mutation admission.

111. In-flight Shutdown

Existing syscall may complete; result is reconciled before terminal classification.

112. RecoveryRequired

Use RecoveryRequired when actual mutation state cannot be safely determined.

113. Manual Recovery

Administrative recovery must be explicit and audited.

114. No Manual Path Delete

Recovery UI/CLI must not offer arbitrary path deletion as shortcut.

115. Executor API

Recommended conceptual API:

```rust
fn execute(
    op: PlannedOperation,
    auth: AuthorizedExecutionContext,
    proof: SafetyProof,
    reservation: ResourceReservation,
) -> ExecutionReceipt;
```

116. Receipt

Receipt records actual syscall attempt and provisional result.

117. Receipt Immutable

Once published, receipt cannot be edited; corrections are new events.

118. Serialization

ExecutionReceipt DTO versioned.

119. Audit Correlation

Receipt must carry JobId/OperationId/AttemptId.

120. Testability

Executor must depend on fakeable filesystem primitive abstraction.

121. Unit Tests

Test each operation/error mapping without real filesystem.

122. Integration Tests

Test real temp filesystem for file/directory/symlink behavior.

123. Race Tests

Replace candidate between safety validation and mutation.

124. Mount Tests

Test mount boundary when supported by test environment.

125. Permission Tests

Test EACCES/EROFS/EBUSY.

126. Crash Tests

Inject crash at journal boundaries and verify recovery classification.

127. Cancellation Tests

Inject cancellation before, between, and during operation phases.

128. Timeout Tests

Verify no new mutation after deadline.

129. Idempotency Tests

Repeat same operation after success, failure, and unknown result.

130. Property Tests

Properties:

- no mutation without SafetyProof
- no operation outside target
- no scope expansion
- unknown never becomes success without verification

131. Fuzzing

Fuzz operation DTOs, path encodings, error mappings, and recursive trees.

132. Definition of Done

Executor production-ready jika:

- single mutation boundary
- typed operations
- SafetyProof required
- no shell command authority
- FD/root safety
- identity revalidation
- bounded recursion
- bounded resources
- cancellation/deadline
- retry classification
- durable attempt journal
- unknown outcome support
- verifier handoff
- crash recovery
- audit/metrics
- race/crash/property tests

133. Final Invariants

1. Executor adalah mutation boundary.
2. Tidak ada mutation tanpa SafetyProof.
3. Tidak ada mutation tanpa Authorization context.
4. Operation selalu typed.
5. Raw shell command bukan operation.
6. Path string bukan authority.
7. Final identity harus direvalidasi.
8. Replacement object tidak boleh dianggap object lama.
9. Symlink safety harus enforced.
10. Mount boundary harus enforced.
11. Read-only mutation harus gagal.
12. Retry harus bounded.
13. Identity mismatch tidak boleh blind retry.
14. AttemptId berubah pada retry.
15. OperationId tetap.
16. Resource reservation diperlukan.
17. Cancellation tidak mengubah mutation history.
18. Timeout during syscall dapat menghasilkan unknown.
19. Unknown tidak boleh dipublish sebagai success.
20. Successful syscall membutuhkan verification.
21. Executor tidak menetapkan Job terminal state secara langsung.
22. Crash during mutation membutuhkan reconciliation.
23. Restart tidak boleh blind resume.
24. Duplicate execution harus idempotent/reconciled.
25. Expired authorization tidak boleh execute.
26. Stale generation tidak boleh execute.
27. Shutdown mencegah mutation baru.
28. Audit identity lengkap dan redacted.
29. Mutation surface harus dapat diaudit secara static review.
30. Tidak ada alternate destructive path di luar Executor.
