71.md — Policy Engine, Rule Evaluation, Protection, Exceptions, Budgets, Decision Provenance, and Fail-Closed Contract

Tujuan

Policy Engine menerjemahkan configuration + target semantics + candidate facts + runtime context menjadi PolicyDecision yang deterministic.

Policy tidak menemukan filesystem, tidak melakukan mutation, dan tidak menggantikan Safety atau Authorization.

Pipeline:

Candidate + EffectiveConfig + RuntimeContext
                 │
                 ▼
             PolicyEngine
                 │
                 ▼
          PolicyDecision
                 │
                 ▼
              Planner

1. Policy Decision

Decision harus typed, bukan bool.

2. PolicyDecision

Contoh:

```rust
pub enum PolicyDecision {
    Allow(PolicyPermit),
    Deny(PolicyDeny),
    Skip(PolicySkip),
    Unknown(PolicyUnknown),
}
```

3. Allow != Authorization

Policy allow hanya menyatakan candidate memenuhi policy.

4. Deny

Deny berarti operation tidak boleh direncanakan berdasarkan policy saat ini.

5. Skip

Skip adalah non-error exclusion yang dapat dipublikasikan sebagai result.

6. Unknown

Unknown berarti fakta atau policy context tidak cukup untuk keputusan aman.

7. Unknown Is Not Allow

Unknown harus fail-closed untuk destructive operation.

8. Determinism

Input yang sama harus menghasilkan decision yang sama.

9. Inputs

Policy dapat menerima:

- Candidate
- TargetDescriptor
- EffectiveConfig
- RuntimeSnapshot
- Resource availability
- maintenance mode
- job intent

10. No Hidden I/O

Policy sebaiknya tidak melakukan arbitrary filesystem I/O.

Jika fakta tambahan dibutuhkan, Scanner/Platform Adapter harus menyediakan observation.

11. No Mutation

Policy tidak boleh memanggil delete/reclaim/trim.

12. No Authorization Grant

Policy tidak boleh membuat AuthorizationId atau capability token.

13. Rule Identity

Setiap rule mempunyai typed RuleId.

14. Rule Ordering

Rule evaluation order harus explicit dan deterministic.

15. Rule Priority

Priority tidak boleh membuat safety rule lebih permissive.

16. Deny Precedence

Hard deny/protection harus mengalahkan generic allow.

17. Protected Target

Protected target harus mempunyai hard deny atau explicit restricted operation matrix.

18. System Critical

System-critical paths tidak boleh menjadi deletion candidate hanya karena path cocok cache pattern.

19. Target Kind

Policy harus menggunakan TargetKind, bukan hanya string path.

20. Target Scope

Policy harus mempertimbangkan user/package/storage scope.

21. Package Allowlist

Package allowlist hanya mempengaruhi policy eligibility, bukan filesystem authority.

22. Package Denylist

Denylist harus mempunyai precedence yang jelas.

23. Package Identity

Gunakan typed PackageName/UserId.

24. Empty Package List

Semantics empty list harus explicit: none, all, atau disabled; jangan ambigu.

25. Default

Default policy harus conservative.

26. Configuration Binding

PolicyDecision harus menyimpan ConfigGeneration.

27. Catalog Binding

PolicyDecision harus menyimpan CatalogGeneration.

28. Config Reload

Decision yang dibuat dengan config lama tidak otomatis valid setelah config reload.

29. Catalog Change

Target topology change dapat invalidate decision.

30. Runtime Context

Thermal, battery, charging, screen, pressure, maintenance state dapat mempengaruhi policy.

31. Runtime Context Is Snapshot

Runtime context adalah observation dan dapat stale.

32. Safety Context

Runtime policy tidak menggantikan final SafetyGate.

33. Resource Context

Resource availability dapat menentukan defer/deny, tetapi tidak boleh mengubah target safety.

34. Maintenance Mode

Maintenance mode harus mempunyai explicit policy semantics.

35. Manual Mode

Manual request tidak otomatis bypass policy protection.

36. Force Mode

Force harus typed intent dan dibatasi policy.

37. Force Cannot Bypass Safety

Force tidak pernah menghilangkan TrustedRoot/identity/mount safety.

38. Force Cannot Grant Arbitrary Scope

Force tidak boleh memperluas target scope di luar authorization model.

39. Age Policy

Age threshold harus typed Duration.

40. Size Policy

Size threshold harus typed ByteCount.

41. Percentage Policy

Percentage menggunakan bounded value object.

42. Temperature Policy

Temperature menggunakan typed unit.

43. Arithmetic

Semua threshold calculation harus checked.

44. Overflow

Overflow policy calculation menghasilkan explicit invalid/unknown, bukan wrap.

45. Negative Values

Threshold yang tidak valid ditolak saat config validation.

46. Rule Composition

Rules sebaiknya berupa typed predicates + decision effects.

47. Boolean Explosion

Hindari kombinasi boolean seperti `allow_cache && !protected && force || manual` yang sulit diaudit.

48. Explicit AST

Complex policy dapat direpresentasikan sebagai typed AST.

49. Predicate Types

Contoh:

- TargetKindIs
- PackageIs
- UserIs
- AgeAtLeast
- SizeAtLeast
- PathMatchesApprovedPattern
- RuntimeStateIs
- Protected
- CapabilityAvailable

50. Effects

Effect minimal:

- Allow
- Deny
- Skip
- RequireConfirmation
- Defer

51. RequireConfirmation

Confirmation adalah authorization/UI concern, tetapi policy dapat meminta confirmation state.

52. Defer

Defer berarti candidate belum actionable sekarang, bukan denied forever.

53. Deny Reason

Setiap deny mempunyai typed PolicyReason.

54. Reason Stability

Reason code harus stabil untuk CLI/UI/metrics.

55. Human Message

Human-readable message bukan machine contract.

56. Provenance

Decision harus menyimpan rule IDs yang menghasilkan keputusan.

57. Rule Trace

Debug mode dapat menyimpan evaluation trace.

58. Production Logging

Default logging tidak perlu mencetak seluruh trace/path.

59. Explain API

CLI/UI dapat meminta explain decision secara explicit.

60. Explain Must Be Read-only

Explain tidak boleh memodifikasi policy/runtime state.

61. Rule Version

Ruleset harus mempunyai version/fingerprint.

62. Policy Fingerprint

Decision dapat menyimpan fingerprint untuk reproducibility.

63. Config Fingerprint

EffectiveConfig fingerprint berbeda dari ConfigGeneration dan dapat dipakai untuk audit.

64. Rule Update

Ruleset change harus invalidates relevant plans/authorizations.

65. Exception Rules

Exception harus explicit, scoped, typed, bounded, dan auditable.

66. Exception Scope

Exception dapat berlaku untuk target/package/rule/job, tetapi scope harus narrow.

67. Exception Expiration

Temporary exception harus mempunyai expiry/deadline.

68. No Permanent Emergency Bypass

Emergency flag tanpa expiration adalah unsafe design.

69. Exception Precedence

Exception tidak boleh override hard safety deny.

70. Protection Rules

Protection rules harus mempunyai precedence tertinggi di policy layer.

71. Protected Package

Protected package list harus normalized typed PackageName.

72. Protected User

Critical user/system scopes harus explicit.

73. Protected Target

Descriptor safety classification menjadi input hard protection.

74. Custom Rules

Custom regex/path rules tidak boleh menghasilkan authority outside target scope.

75. Regex Safety

Regex harus bounded/compiled once dan tidak boleh membuka ReDoS risk.

76. Path Pattern

Path pattern harus relatif terhadap target root.

77. Glob Semantics

Glob matching harus deterministic dan documented.

78. Case Semantics

Case-sensitive behavior harus mengikuti target filesystem semantics.

79. Unicode

Do not lossy-normalize identity strings.

80. Rule Conflict

Conflicting allow/deny rules harus mempunyai deterministic precedence.

81. Conservative Conflict

Jika precedence tidak dapat ditentukan, decision = Unknown/Deny.

82. Policy Budget

Jumlah rule evaluation harus bounded.

83. Candidate Budget

Policy harus tetap bounded ketika menerima large candidate stream.

84. Streaming Evaluation

Policy harus dapat mengevaluasi candidate secara streaming.

85. No Global Unbounded State

Policy tidak boleh menyimpan seluruh candidate set tanpa alasan/limit.

86. Aggregation

Jika policy membutuhkan aggregate, gunakan bounded counters/sets.

87. Quota

Policy dapat mempunyai byte/count quota.

88. Quota Semantics

Quota harus jelas apakah hard per-job, per-target, per-package, atau global.

89. Quota Enforcement

Planner/ResourceManager tetap bertanggung jawab terhadap actual resource budget; policy quota bukan replacement.

90. Pressure Policy

System pressure dapat mengubah eligibility, misalnya aggressive reclaim.

91. Pressure Safety

Pressure tidak boleh menurunkan safety level.

92. Thermal Policy

Thermal state dapat menurunkan concurrency atau defer operation.

93. Battery Policy

Battery state dapat menentukan whether background cleanup is eligible.

94. Charging Policy

Charging state dapat menjadi condition, bukan filesystem authority.

95. Screen State

Screen-off condition harus diperlakukan sebagai runtime hint/scheduler condition.

96. Maintenance Window

Time window policy harus menggunakan monotonic scheduling plus wall-clock only for calendar semantics.

97. Clock Changes

Wall clock adjustment tidak boleh menyebabkan negative duration/unsafe expiry.

98. Deadline

Policy decision may include deadline after which re-evaluation is required.

99. Staleness

Policy decision must be considered stale when bound config/catalog generation changes.

100. Re-evaluation

Planner dapat re-evaluate before commit if context changed.

101. No Silent Drift

Candidate yang sudah allow tidak otomatis tetap allow setelah policy context berubah.

102. Protected File

Specific protected file/path rules should use explicit target-relative identity.

103. Cache Heuristics

Heuristic cache classification harus conservative.

104. Filename Heuristic

Nama `cache`, `.cache`, `tmp` saja tidak cukup untuk destructive allow.

105. Extension Heuristic

Extension bukan proof bahwa data ephemeral.

106. Age Heuristic

Age adalah evidence, bukan identity.

107. Size Heuristic

Size adalah eligibility signal, bukan safety proof.

108. Content Heuristic

Content inspection harus explicit dan bounded jika digunakan.

109. Unknown Class

Unknown semantic class harus non-destructive by default.

110. Target-Specific Policy

TargetKind dapat menyediakan policy profile.

111. Policy Profile

Profile harus immutable/versioned.

112. Platform Policy

Android-specific policy rules harus berada di platform layer/profile, bukan generic path hacks.

113. OEM Policy

OEM exception harus isolated dan auditable.

114. User Policy

User configuration dapat memilih profile, tetapi tidak dapat menghapus platform hard safety constraints.

115. Config Validation

Policy-invalid config harus ditolak sebelum EffectiveConfig publication.

116. Dynamic Reload

Policy engine harus atomically switch EffectiveConfig.

117. In-flight Job

In-flight job tetap terikat generation lama sampai transition boundary yang terdokumentasi.

118. New Job

New job menggunakan current EffectiveConfig.

119. Plan Compatibility

Planner harus memastikan PolicyDecision dan Plan memakai compatible generations.

120. Authorization Compatibility

Authorization harus dibuat berdasarkan policy decision yang current.

121. Safety Compatibility

Safety final gate tetap wajib meski policy allow.

122. Result Accounting

Policy skip/deny harus dibedakan dari execution failure.

123. Metrics

Expose counts by reason/rule/target kind tanpa leaking sensitive path.

124. Audit

Audit policy decision harus immutable.

125. Audit Redaction

Audit path/package data mengikuti privacy/redaction policy.

126. Policy Error

Internal evaluation error tidak boleh berubah menjadi allow.

127. Panic

Policy panic harus dianggap engine failure dan fail-closed.

128. Rule Compilation Error

Ruleset compilation failure tidak boleh publish partial ruleset.

129. Atomic Ruleset Swap

New ruleset hanya aktif setelah seluruh compile/validate selesai.

130. Compatibility

Ruleset schema version harus explicit.

131. Serialization

Persisted policy decision DTO harus versioned.

132. No Authority Through DTO

Deserialized PolicyPermit harus tetap diverifikasi against current generation before use.

133. Test Matrix

Test kombinasi:

- target kind
- package/user scope
- protected status
- age/size
- runtime state
- config generation
- catalog generation
- force/manual
- exceptions

134. Property Testing

Properties:

- hard deny cannot become allow
- unknown cannot become destructive allow
- force cannot bypass safety
- generation mismatch cannot expand authority

135. Fuzzing

Fuzz rule AST, patterns, thresholds, package names, path components, and malformed configuration.

136. Determinism Test

Repeated evaluation with same immutable inputs must produce identical machine decision and reason set.

137. Definition of Done

Policy production-ready jika:

- typed decisions
- deterministic ordering
- explicit precedence
- protected target hard constraints
- Unknown fail-closed
- typed thresholds
- bounded evaluation
- generation binding
- exception expiry
- no mutation/I/O authority
- provenance/audit
- atomic ruleset reload
- fuzz/property tests

138. Final Invariants

1. Policy tidak melakukan mutation.
2. Policy tidak memberi authorization.
3. Policy tidak menggantikan Safety.
4. Allow bukan Authorization.
5. Unknown bukan Allow.
6. Hard deny selalu menang atas generic allow.
7. Protected target tidak boleh dibuka oleh force.
8. Force tidak bypass safety.
9. ConfigGeneration harus terikat.
10. CatalogGeneration harus terikat.
11. Runtime context adalah snapshot.
12. Policy decision dapat menjadi stale.
13. Exception harus scoped dan auditable.
14. Temporary exception harus expiry-bound.
15. Rule conflict harus deterministic atau fail-closed.
16. Arithmetic threshold harus checked.
17. Candidate stream harus bounded.
18. Policy error tidak boleh menghasilkan allow.
19. Ruleset reload harus atomic.
20. Policy provenance harus dapat diaudit.
