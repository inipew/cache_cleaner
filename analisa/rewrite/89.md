# 89.md — Concurrency Model, Ownership, Locking, dan Parallel Execution

## Tujuan

Concurrency harus ditentukan sebagai bagian dari correctness, bukan sekadar optimasi performance.

Cache cleaner dapat mempunyai scheduler, IPC handlers, scanner, planner, workers, verifier, recovery, dan resource manager yang hidup bersamaan. Tanpa model ownership yang jelas, sistem dapat menghasilkan duplicate mutation, stale state, deadlock, starvation, atau race terhadap filesystem.

Prinsip utama:

```text
parallelism boleh meningkatkan throughput
parallelism tidak boleh mengurangi safety
```

## 1. Actor Model

Komponen utama:

```text
IPC
  ↓
Scheduler
  ↓
Job/Plan
  ↓
Worker
  ├── Executor
  └── Verifier

Recovery
ResourceManager
PlatformAdapter
DurableStore
```

Setiap actor mempunyai authority yang berbeda.

## 2. Scheduler Is Coordinator

Scheduler menentukan:

- kapan Job dapat berjalan
- Job priority
- resource admission
- worker assignment
- wakeup

Scheduler tidak melakukan filesystem mutation.

## 3. Worker Is Execution Owner

Worker menjalankan execution context yang sudah dibentuk.

Worker tidak boleh mengubah plan secara diam-diam atau membuat mutation di luar authorized operation set.

## 4. One Logical Operation, One Active Executor

Pada kondisi normal hanya boleh ada satu active executor untuk satu `OperationId`.

Concurrency terhadap operation yang sama hanya dapat terjadi sebagai recovery race dan harus ditolak melalui durable claim/lease/version.

## 5. Independent Operations

Operation dapat berjalan parallel jika:

- target identity independent
- dependency graph mengizinkan
- resource budget tersedia
- filesystem semantics aman
- policy mengizinkan

Contoh:

```text
Target A → O1
Target B → O2
```

dapat parallel jika tidak ada shared exclusion.

## 6. Same Target

Operation pada target yang sama default-nya harus conservative.

Contoh:

```text
A/cache1 → delete
A/cache2 → delete
```

Boleh parallel hanya jika target contract dan filesystem semantics membuktikan aman.

Jika tidak, gunakan target-level serialization.

## 7. Parent/Child Dependency

Operation graph harus menentukan dependency.

Contoh:

```text
remove child
   ↓
remove parent directory
```

Parent tidak boleh dieksekusi sebelum required children selesai.

## 8. Conflict Detection

Planner harus mendeteksi conflict seperti:

- same path
- ancestor/descendant
- same object identity
- overlapping target
- incompatible maintenance operations

Conflict harus menghasilkan ordering atau explicit rejection.

## 9. Lock Scope

Lock digunakan hanya ketika benar-benar diperlukan.

Jenis lock dapat meliputi:

- global scheduler state
- Job state
- target lock
- filesystem lock
- resource lock
- operation claim

Jangan menggunakan satu global mutex untuk seluruh executor.

## 10. Lock Hierarchy

Urutan acquisition harus konsisten.

Contoh:

```text
Job
 ↓
Target
 ↓
Filesystem resource
 ↓
Operation-local
```

Actual hierarchy harus ditetapkan satu kali dan didokumentasikan.

## 11. No Lock Inversion

Jangan mempunyai dua code path:

```text
A: Target → Resource
B: Resource → Target
```

karena dapat menghasilkan deadlock.

## 12. No Lock Across Blocking

Lock tidak boleh ditahan selama:

- IPC wait
- resource wait
- scheduler wait
- long filesystem traversal
- sleep

Acquire → critical section → release.

## 13. Durable State Concurrency

In-memory mutex tidak cukup untuk correctness antar process/restart.

Durable state harus menggunakan transaction/version/CAS.

## 14. Optimistic Concurrency

Job/Attempt/Operation records sebaiknya mempunyai version.

Transition menggunakan expected version.

Jika version berubah, actor harus reload/reconcile, bukan overwrite.

## 15. Execution Claim

Sebelum mutation:

```text
Operation O1
version 4
 ↓
claim by W1
version 5
```

Worker lain tidak boleh mengambil O1 dengan version lama.

## 16. Lease

Untuk long-running work, execution claim dapat mempunyai lease/heartbeat.

Lease hanya menyatakan ownership/liveness, bukan mutation success.

## 17. Lease Expiry

Lease expiry harus melalui recovery decision.

Jangan langsung menganggap worker mati hanya karena heartbeat terlambat sekali.

## 18. Stale Message

Worker message membawa:

- JobId
- AttemptId
- OperationId
- WorkerId
- lease/version

Message dengan identity/version stale ditolak.

## 19. Cancellation Race

Race berikut harus didefinisikan:

```text
cancel request
      ↕
mutation start
```

Jika cancellation menang sebelum mutation boundary → Cancelled.

Jika mutation sudah dimulai → verification/reconciliation semantics.

## 20. Timeout Race

Timer tidak boleh secara asynchronous mengubah operation menjadi Failed sementara executor masih berada di critical mutation sequence tanpa synchronization.

Timeout harus menjadi event yang diproses melalui lifecycle state machine.

## 21. Shutdown Race

Shutdown dapat datang ketika worker sedang:

- scanning
- planning
- waiting resource
- executing
- verifying

Setiap phase mempunyai shutdown semantics berbeda.

## 22. Worker Stop

Worker boleh dihentikan cooperative pada safe point.

Hard termination hanya boleh dilakukan jika external mechanism benar-benar diperlukan dan konsekuensi Unknown/recovery ditangani.

## 23. Scanner Concurrency

Scanner dapat parallelize traversal jika resource policy mengizinkan.

Tetapi candidate ordering harus tetap deterministic atau secara eksplisit unordered.

Planner tidak boleh bergantung pada scheduling order thread.

## 24. Deterministic Planning

Input yang sama:

```text
Candidate set
ConfigGeneration
CatalogGeneration
Policy
```

harus menghasilkan Plan yang sama tanpa bergantung pada thread timing.

## 25. Candidate Deduplication

Parallel scanner dapat menemukan candidate yang sama melalui overlapping roots.

Deduplication harus dilakukan berdasarkan identity yang benar, bukan hanya path string.

## 26. Verifier Concurrency

Verifier dapat parallel untuk operation independent.

Namun observation terhadap target yang sama harus memperhatikan mutation ordering.

## 27. Verification After Concurrent Mutation

Verifier tidak boleh menganggap state stabil jika operation lain masih dapat memodifikasi object yang sama.

Gunakan dependency/lock/generation untuk memastikan evidence valid.

## 28. Resource Manager Coordination

Worker meminta resource sebelum execution.

Jika tidak tersedia:

```text
WaitingResources
```

dan worker block/relinquish CPU.

## 29. Backpressure

Scheduler tidak boleh membuat worker sebanyak queue length.

Bounded worker count dan bounded queue menjaga memory/CPU tetap terkendali.

## 30. Priority

Priority dapat menentukan urutan scheduling, tetapi tidak boleh bypass:

- safety
- authorization
- resource limit
- dependency

## 31. Starvation

High-priority work tidak boleh membuat low-priority recovery/verification starvation.

Recovery yang dibutuhkan untuk consistency dapat memiliki reserved capacity.

## 32. Fairness

Scheduler dapat menggunakan:

- weighted fairness
- aging
- bounded work quantum
- per-target quotas

sesuai kompleksitas yang diperlukan.

## 33. Preemption

Preemption paling aman pada non-mutating phase.

Pada mutation phase:

```text
finish critical sequence
→ verify
→ release
```

bukan hard-stop sembarang.

## 34. Global vs Local Locks

Gunakan global lock hanya untuk truly global state.

Filesystem operations sebaiknya menggunakan local/target-scoped synchronization bila memungkinkan.

## 35. Lock-Free Tidak Otomatis Lebih Aman

Menghilangkan mutex tidak menyelesaikan correctness jika durable state masih mengalami race.

Gunakan primitive yang paling mudah diaudit.

## 36. Async Runtime

Jika async digunakan, hindari blocking filesystem/syscalls pada async executor thread kecuali memang menggunakan blocking pool yang tepat.

Async task cancellation juga harus menghormati mutation boundary.

## 37. Synchronous Alternative

Untuk daemon dengan workload dominan filesystem dan kebutuhan power-neutral idle, synchronous event loop + bounded worker threads dapat lebih mudah diaudit daripada async runtime yang kompleks.

Pilihan harus berdasarkan workload dan dependency behavior, bukan tren.

## 38. Memory Concurrency

Shared collections harus bounded.

Jangan membuat satu giant shared `Vec<Candidate>` hanya agar worker mudah mengaksesnya.

Streaming/chunking lebih aman untuk filesystem besar.

## 39. Error Propagation

Concurrent worker error tidak boleh langsung mengubah Job state tanpa aggregation/state-machine semantics.

Worker mengirim structured result.

Coordinator menentukan transition.

## 40. Result Aggregation

Partial results harus immutable setelah operation finalized.

Aggregator harus deduplicate berdasarkan OperationId.

## 41. Panic Isolation

Panic pada worker tidak boleh merusak seluruh durable state.

Panic harus ditangkap pada boundary yang tepat atau process crash harus ditangani melalui normal recovery protocol.

## 42. Resource Release on Panic

RAII memastikan process-local resource dilepas saat unwind.

Durable claims tetap memerlukan recovery jika process mati sebelum release.

## 43. Database Connection Concurrency

Durable store harus mempunyai model connection/transaction yang jelas.

Jangan membiarkan worker membuat transaction panjang yang saling blocking.

## 44. Event Bus Concurrency

Event queue harus bounded.

Event handler harus idempotent dan tidak boleh mengandalkan ordering yang tidak dijamin.

## 45. Wakeup Coalescing

Banyak concurrent event harus menjadi satu bounded scheduler evaluation bila semantics memungkinkan.

## 46. Recovery vs New Work

Recovery untuk unresolved mutation mempunyai precedence atas optional new cleanup pada target yang sama.

Jangan membuat operation baru sebelum consistency lama jelas.

## 47. Replanning Race

Jika ConfigGeneration/CatalogGeneration berubah saat planning:

```text
plan stale
→ discard/replan
```

bukan menjalankan plan lama secara diam-diam.

## 48. Authorization Race

Authorization revoked/expired saat menunggu resource harus membuat execution claim tidak valid lagi.

Fresh authorization diperlukan sebelum mutation.

## 49. Safety Race

Safety check dilakukan sedekat mungkin dengan mutation boundary.

Check yang dilakukan terlalu awal hanya merupakan evidence awal.

## 50. Mount Race

Mount change harus menginvalidasi relevant target assumptions.

Worker tidak boleh terus menggunakan target descriptor lama tanpa revalidation.

## 51. Concurrent Target Replacement

Object dapat hilang lalu diganti saat worker berjalan.

Identity-aware operation mencegah deletion terhadap replacement.

## 52. Testing Concurrency

Minimal test:

- two workers claim same operation
- cancellation vs execution
- timeout vs execution
- shutdown vs worker
- mount change vs operation
- config reload vs planning
- authorization expiry vs resource wait
- duplicate event vs transition
- stale worker message
- recovery vs new scheduler request

## 53. Race Detector

Gunakan tooling seperti ThreadSanitizer bila compatible dengan target/toolchain untuk shared-memory race detection.

Selain itu gunakan stress tests dan deterministic scheduling hooks.

## 54. Deterministic Test Scheduler

Production scheduler timing sulit diuji jika bergantung wall clock/thread scheduling.

Test harness sebaiknya dapat menggunakan virtual/manual clock dan controlled event delivery.

## 55. Concurrency Limits

Semua parallelism harus mempunyai upper bound:

```text
max workers
max scanner tasks
max verifier tasks
max open FDs
max queued jobs
max event queue
```

## 56. Definition of Done

Concurrency production-ready jika:

- ownership jelas
- one active executor per operation
- durable CAS/versioning
- lease/recovery semantics
- lock hierarchy
- no blocking under lock
- bounded workers/queues
- deterministic planning
- identity-aware deduplication
- cancellation/timeout race defined
- shutdown race defined
- recovery precedence defined
- resource admission integrated
- race/stress tests tersedia

## Final Invariants

1. Parallelism tidak boleh mengurangi safety.
2. Satu OperationId hanya memiliki satu active executor normal.
3. AttemptId tetap membedakan execution attempts.
4. Durable state menggunakan version/CAS untuk concurrent transition.
5. Stale worker message tidak boleh mengubah current state.
6. Lease bukan proof of mutation success.
7. Lock hierarchy harus konsisten.
8. Tidak ada indefinite blocking sambil memegang exclusive lock.
9. Worker count dan queue harus bounded.
10. Planner harus deterministic terhadap input yang sama.
11. Candidate deduplication identity-aware.
12. Verifier tidak boleh membaca state yang sedang dimutasi tanpa synchronization semantics.
13. Cancellation race ditentukan oleh mutation boundary.
14. Timeout bukan automatic failure proof.
15. Shutdown harus membangunkan waiter.
16. Recovery unresolved mutation mendapat precedence yang tepat.
17. Safety check harus dekat dengan mutation boundary.
18. Authorization harus valid pada execution time.
19. Mount/identity changes menginvalidasi stale context.
20. Concurrency correctness harus diuji dengan race/stress/fault injection.
