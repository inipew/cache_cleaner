49.md — Filesystem and Platform Change Detection, Event Sources, Mount/User/Package Invalidation, Catalog Refresh, Stale Job Detection, Event Coalescing, Race Handling, and Consistency Recovery Contract

Tujuan

Dokumen ini mendefinisikan bagaimana sistem mendeteksi perubahan filesystem dan platform yang dapat membuat:

```
Candidate
CatalogSnapshot
PolicyDecision
PlannedOperation
AuthorizedPlan
```

menjadi stale.

Cleanup engine bekerja pada sistem yang mutable.

Karena itu asumsi:

```
"state saat scan == state saat execution"
```

tidak boleh digunakan.

Model utama:

```
External Change
      │
      ▼
Event Source
      │
      ▼
Runtime Event
      │
      ▼
Change Classifier
      │
      ▼
Invalidation
      │
      ├── Target
      ├── Catalog
      ├── Job
      └── Platform Snapshot
      │
      ▼
Refresh / Rescan / Replan
      │
      ▼
New Generation
```

1. Prinsip Fundamental

Filesystem, Android state, package state, user state, dan mount topology dapat berubah kapan saja.

Contoh:

```
scan
  │
  ▼
/cache/file.tmp
  │
  ▼
package update
  │
  ▼
/cache/file.tmp berubah
  │
  ▼
old Candidate stale
```
