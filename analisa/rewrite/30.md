Lanjut ke **`ipc/`**. Ini boundary yang mencegah proses lain mengubah daemon privileged menjadi “remote delete API”.

Prinsip utamanya:

> **IPC hanya boleh meminta intent. IPC tidak boleh mengirim authority.**

Jadi request boleh mengatakan:

```text
"jalankan cleanup profile Deep"
```

tetapi tidak boleh mengatakan:

```text
"hapus /data/xxx/yyy"
"anggap saya Root"
"abaikan Safety"
"gunakan target ini walaupun tidak ada di catalog"
```

# 821. Final IPC invariant

```text id="x7p2m4"
1. Peer identity comes from kernel credentials.
2. Role is derived, never supplied by client.
3. Capabilities are server-side.
4. No BypassSafety capability exists.
5. No arbitrary path appears in cleanup request.
6. No arbitrary device appears in maintenance request.
7. Frame sizes are bounded before allocation.
8. Protocol versions are explicit.
9. Stream framing handles partial/multiple frames.
10. Disconnect does not implicitly cancel accepted jobs.
11. Cancellation requires authorization.
12. IPC never executes filesystem operations directly.
13. IPC never bypasses Scheduler.
14. Explain is read-only.
15. Root still passes Safety/Policy.
16. Unauthorized plan capability causes whole-plan rejection.
17. Domain objects are not serialized directly.
18. Sensitive internal details are not exposed to clients.
19. Parser must be fuzzable and side-effect free.
20. IPC failure cannot leave privileged operation half-authorized.
```

Yang menarik, sekarang **tidak ada satu pun input eksternal yang bisa langsung menjadi filesystem authority**.

Input dari:

* CLI
* IPC
* config
* Android state
* kernel state

semuanya akhirnya hanya menghasilkan **intent/fact**, kemudian harus melewati boundary yang tepat.

### Berikutnya: `config/`

Tahap selanjutnya sebaiknya kita desain **configuration system** secara detail, karena config adalah sumber input eksternal kedua setelah IPC. Kita perlu memastikan config bisa mengatur **policy**, tetapi **tidak pernah bisa mengatur security invariants**.

Kita akan bentuk:

```text id="p8m3x7"
RawConfig
    ↓
Syntax Parse
    ↓
Schema Validation
    ↓
Semantic Validation
    ↓
ValidatedConfig
    ↓
EffectivePolicy
    ↓
ConfigSnapshot
```

termasuk **schema versioning, unknown-field rejection, atomic reload, generation number, hard limits vs user limits, profile Conservative/Normal/Deep, target selection tanpa arbitrary path, package exclusion, user scope, maintenance flags, config-file security, dan apa saja yang secara permanen dibuat non-configurable**.
