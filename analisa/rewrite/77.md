# 77.md — Scheduler Implementation, Trigger Evaluation, Admission, Fairness, Persistence, and Recovery Contract

## Tujuan

Scheduler mengubah trigger menjadi keputusan scheduling yang deterministic, bounded, cancellable, dan resource-aware. Scheduler bukan executor dan tidak boleh melakukan filesystem mutation.

## 1. Boundary

```text
Triggers → Scheduler → Job Admission → Queue → Worker
```

Scheduler hanya mengatur kapan dan dengan prioritas apa Job boleh berjalan.

## 2. Trigger Types

Gunakan typed trigger:

```rust
pub enum Trigger {
    Startup,
    Timer,
    Pressure(PressureLevel),
    Manual,
    Event(SystemEvent),
    Recovery,
}
```

## 3. Trigger != Job

Satu trigger dapat menghasilkan nol atau beberapa keputusan; trigger tidak identik dengan Job.

## 4. Debounce

Burst trigger harus didebounce/coalesce agar tidak menghasilkan cleaning storm.

## 5. Manual Trigger

Manual request harus melalui policy, safety, resource, dan authorization seperti scheduled Job.

## 6. Pressure Trigger

Pressure trigger harus membawa evidence/measurement dan timestamp.

## 7. Stale Trigger

Trigger lama tidak boleh memaksa Job jika kondisi sudah berubah.

## 8. Trigger Evaluation

Evaluation harus menggunakan immutable ConfigGeneration dan current system snapshot.

## 9. Config Binding

Scheduled decision menyimpan ConfigGeneration yang digunakan.

## 10. Catalog Binding

Target selection menyimpan CatalogGeneration.

## 11. Re-evaluation

Jika Job menunggu lama, scheduler boleh meminta re-evaluation sebelum admission/execution.

## 12. No Hidden Mutation

Scheduler tidak boleh memanggil delete/trim/sysfs mutation langsung.

## 13. Queue Classes

Minimal dapat dibedakan:

- recovery
- pressure
- scheduled
- manual
- maintenance

Prioritas tidak boleh mengabaikan safety.

## 14. Recovery Priority

Recovery jobs dapat diprioritaskan untuk mengurangi unknown state, tetapi tetap bounded.

## 15. Manual Priority

Manual tidak otomatis berarti highest priority.

## 16. Fairness

Satu trigger source tidak boleh starve source lain tanpa policy yang eksplisit.

## 17. Aging

Queue dapat menggunakan bounded aging untuk mencegah starvation.

## 18. Concurrency

Scheduler harus menghormati ResourceManager dan worker concurrency limits.

## 19. Admission

Scheduler boleh enqueue hanya setelah basic admission checks.

## 20. Admission != Authorization

Admission memutuskan apakah sistem dapat menerima workload sekarang.

Authorization memutuskan capability untuk mutation.

## 21. Capacity

Scheduler harus mempertimbangkan:

- active workers
- memory budget
- IO budget
- operation count
- scan budget
- storage pressure

## 22. Backpressure

Jika queue/budget penuh, scheduler harus menunda atau reject dengan alasan typed.

## 23. Coalescing

Dua scheduled cleaning request yang equivalent dapat digabung jika semantics tetap sama.

## 24. Coalescing Safety

Coalescing tidak boleh menggabungkan Job dengan scope/authorization berbeda secara unsafe.

## 25. Idempotency

Recurring trigger harus memiliki deterministic scheduling identity.

## 26. Schedule Identity

Persisted schedule menggunakan ScheduleId.

## 27. Schedule Definition

Schedule menyimpan interval/calendar, enabled state, timezone semantics jika diperlukan, dan policy reference.

## 28. Timezone

Untuk interval scheduler daemon, gunakan monotonic duration.

Calendar-based schedule harus memiliki explicit timezone.

## 29. Clock Changes

Wall-clock adjustments tidak boleh membuat interval scheduler berjalan ribuan kali atau melewatkan safety deadline.

## 30. Missed Schedule

Setelah downtime, scheduler harus memiliki policy:

- skip
- run once
- catch up bounded

Default harus bounded, bukan unbounded catch-up.

## 31. Jitter

Recurring jobs dapat memakai bounded jitter untuk menghindari synchronized bursts.

## 32. Deadline

Setiap queued Job dapat mempunyai admission/execution deadline.

## 33. Deadline Expiry

Expired Job menjadi TimedOut/Cancelled sesuai lifecycle contract, bukan tetap queue selamanya.

## 34. Retry

Scheduler tidak menentukan filesystem retry secara detail; ia mengorkestrasi retry Attempt sesuai retry classification.

## 35. Retry Backoff

Backoff harus bounded dan persistable bila Job durable.

## 36. Retry Jitter

Backoff jitter harus deterministic enough for tests dan bounded.

## 37. Retry Limit

Max attempts adalah policy/resource constraint.

## 38. Retry Safety

Unknown mutation outcome tidak boleh dijadwalkan sebagai ordinary retry.

## 39. Recovery Queue

RecoveryRequired memiliki jalur reconciliation khusus.

## 40. Worker Death

Worker lease expiry menghasilkan recovery event, bukan langsung retry mutation.

## 41. Shutdown

Scheduler berhenti admitting new Jobs sebelum worker shutdown.

## 42. Drain

Shutdown mode:

```text
Running → StopAdmission → Drain/Cancel → StopWorkers
```

## 43. Forced Shutdown

Force shutdown tidak boleh mengubah unknown mutation menjadi failed.

## 44. Startup

Startup scheduler harus menunggu store recovery dan platform snapshot minimum sebelum scheduling normal.

## 45. Recovery First

Unresolved recovery state harus diperhitungkan sebelum new destructive workload.

## 46. Event Loop

Scheduler loop harus bounded terhadap satu event.

Tidak boleh melakukan scan besar/blocking IO tanpa delegation.

## 47. Event Loss

Periodic reconciliation menutup kemungkinan event hilang.

## 48. Event Ordering

Sequence number lebih authoritative daripada wall-clock timestamp.

## 49. Duplicate Event

Scheduler harus idempotent terhadap duplicate trigger/event.

## 50. Stale Event

Event yang generation-nya stale tidak boleh mengganti keputusan baru secara langsung.

## 51. Snapshot

Scheduler evaluation menggunakan snapshot atomik:

```rust
struct SchedulingSnapshot {
    config_generation: ConfigGeneration,
    catalog_generation: CatalogGeneration,
    system: SystemSnapshot,
    queue: QueueSnapshot,
    resources: ResourceSnapshot,
}
```

## 52. Deterministic Decision

Input snapshot yang sama harus menghasilkan scheduling decision yang sama.

## 53. Decision Reason

Setiap admission/skip/defer/reject harus mempunyai typed reason.

## 54. Observability

Metrics minimal:

- trigger count
- coalesced count
- queued
- admitted
- deferred
- rejected
- execution latency
- queue latency
- retry count
- recovery count

## 55. Queue Persistence

Queued durable Jobs harus dapat direkonstruksi setelah restart.

## 56. In-Memory Queue

Queue memory adalah acceleration layer, bukan source of truth.

## 57. Rebuild Queue

Startup rebuild harus deterministic berdasarkan persisted Job state + priority + creation sequence.

## 58. Duplicate Queue Entry

Duplicate queue entries tidak boleh menghasilkan concurrent duplicate execution.

## 59. Claim

Worker harus atomically claim Job/Attempt sebelum execution.

## 60. Scheduler/Worker Separation

Scheduler tidak boleh memegang exclusive execution lock selama Job menunggu.

## 61. Resource Wait

Resource starvation harus dilaporkan sebagai waiting state, bukan scheduler busy-loop.

## 62. Wakeup

Resource release/event harus membangunkan scheduler/queue evaluator.

## 63. Polling

Polling interval harus bounded dan adaptive.

## 64. Idle Behavior

Saat tidak ada work, scheduler harus menggunakan bounded sleep/event wait.

## 65. Power Awareness

Android daemon harus mempertimbangkan screen/power/thermal snapshot sebagai policy inputs bila konfigurasi mendukung.

## 66. Thermal

Scheduler tidak boleh memulai workload yang dilarang thermal policy.

## 67. Pressure Escalation

Higher pressure dapat meningkatkan priority tetapi tidak boleh bypass safety/authorization.

## 68. Resource Pressure

Jika scheduler sendiri mengalami resource pressure, ia harus degrade gracefully.

## 69. Queue Limits

Max queued Jobs harus bounded.

## 70. Submission Flood

Manual/API flood harus menghasilkan backpressure/rate limit.

## 71. Per-Source Fairness

Rate limit dapat diterapkan per source/scope.

## 72. Priority Inversion

High priority Job yang menunggu resource held oleh low priority Job harus memiliki mitigation yang jelas melalui ResourceManager.

## 73. Scheduler Locking

Jangan menggunakan global mutex untuk seluruh execution lifecycle.

## 74. Long Operations

Scheduler tidak boleh menunggu filesystem operation selesai dalam event-loop critical section.

## 75. Config Reload

Config reload menghasilkan ConfigGeneration baru. Existing running Job tidak boleh berubah policy retroaktif kecuali contract eksplisit mengizinkan re-evaluation.

## 76. Existing Job

Job harus tetap terikat pada config snapshot yang telah di-authorize sampai safe re-evaluation boundary.

## 77. New Job

New Job selalu menggunakan current effective config.

## 78. Catalog Refresh

Catalog refresh tidak otomatis cancel Job; ia membuat generation mismatch yang akan diperiksa pada boundary berikutnya.

## 79. Manual Cancel

Cancel request menjadi durable lifecycle transition.

## 80. Cancellation Precedence

Cancellation dapat mencegah execution sebelum mutation boundary.

Setelah mutation dimulai, cancellation menjadi best-effort + verification/reconciliation.

## 81. Scheduler Persistence

Persist schedule changes atomically.

## 82. Disable Schedule

Disabling schedule mencegah new Jobs tetapi tidak membatalkan running Job secara implisit.

## 83. Schedule Migration

Schema migration tidak boleh duplicate fire recurring schedules.

## 84. Monotonic Sequence

Scheduled occurrence harus memiliki unique sequence/occurrence identity.

## 85. Crash Between Fire and Persist

Gunakan occurrence idempotency agar crash tidak menghasilkan duplicate Job.

## 86. Crash Between Persist and Enqueue

Persisted Job harus dapat direbuild ke queue setelah restart.

## 87. Crash Between Claim and Worker Start

Lease expiry/recovery harus menangani state tersebut.

## 88. Test Matrix

Uji:

- duplicate triggers
- burst triggers
- clock jump
- reboot
- worker death
- queue full
- resource exhaustion
- config reload
- catalog generation change
- cancellation race
- shutdown race

## 89. Definition of Done

Scheduler production-ready jika:

- trigger typed
- queue durable/rebuildable
- admission bounded
- priority deterministic
- fairness tersedia
- retry bounded
- unknown outcome tidak blind-retry
- generation binding diterapkan
- resource admission terintegrasi
- shutdown safe
- duplicate trigger idempotent
- clock changes safe
- missed schedule policy explicit
- crash windows diuji

## 90. Final Invariants

1. Scheduler tidak melakukan mutation.
2. Trigger bukan Job identity.
3. Memory queue bukan source of truth.
4. Queue entry tidak sama dengan execution ownership.
5. Admission bukan authorization.
6. Priority tidak pernah bypass safety.
7. Unknown mutation bukan ordinary retry.
8. Duplicate trigger aman.
9. Crash sebelum enqueue tidak kehilangan durable Job.
10. Crash setelah enqueue tidak menghasilkan duplicate execution.
11. Worker claim harus atomic.
12. ConfigGeneration binding dihormati.
13. CatalogGeneration mismatch diperiksa.
14. Shutdown menghentikan admission sebelum worker shutdown.
15. Scheduler selalu bounded terhadap workload dan event.
