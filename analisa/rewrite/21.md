Lanjut ke **`safety/`**. Ini layer yang membedakan daemon cleanup biasa dengan daemon privileged yang benar-benar punya security boundary.

Prinsip besarnya:

> **Policy boleh berubah. Safety invariant tidak boleh berubah karena config, profile, CLI, atau privilege level.**

# 275. Pisahkan 3 konsep

Kita jangan mencampur:


### Policy

> Apakah sekarang kita memang ingin membersihkannya?

```text id="n8m4q1"

   ↓

   ↓

   ↓

   ↓

```

# 322. Safety invariants final

Saya akan jadikan checklist code review:

```text id="m2q8r4"
1. Unknown TargetId is rejected.
2. Arbitrary paths cannot enter the safety pipeline.
3. Relative paths cannot contain "..".
4. Root identity must match.
5. Entry identity must match.
6. Device identity must match.
7. Symlinks are never followed.
8. Unsupported file types are rejected.
9. CE-locked targets are not touched.
10. Invalid users are rejected.
11. Invalid package identity is rejected where required.
12. Protected targets cannot enter cleanup.
13. Safety cannot be weakened by profile.
14. Safety cannot be weakened by CLI.
15. Safety cannot be weakened by IPC role.
16. SafetyProof cannot be constructed by arbitrary callers.
17. Execution revalidates stale plans.
18. Safety never performs destructive operations.
```

# 323. Sekarang pipeline kita sudah semakin solid

```text id="r6m1q9"
                  Scanner
                     │
                     ▼
                 Candidate
                     │
                     ▼
            ┌────────────────┐
            │ SafetyValidator│
            └───────┬────────┘
                    │
          ┌─────────┴─────────┐
          │                   │
          ▼                   ▼
 SafetyValidated            Reject
          │
          ▼
       Policy
          │
     ┌────┴────┐
     ▼         ▼
   Allow     Reject/Defer
     │
     ▼
   Planner
```

Yang berikutnya adalah **`policy/`**.

Di sana kita akan membuat policy engine yang **tidak bisa mengubah safety invariant**, tetapi cukup fleksibel untuk:

* `Conservative / Normal / Deep`
* age threshold
* target enable/disable
* user scope
* storage state
* screen/idle requirement
* thermal state
* size/budget
* maintenance flags
* package exclusions
* `dry-run`
* dan terutama **`PolicyTrace`** supaya `explain` bisa menjawab *mengapa file A diizinkan, file B ditolak, dan file C ditunda* tanpa giant `if/else`.
