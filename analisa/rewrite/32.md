# 944. Target Catalog invariant

```text id="m7q2x4"
1. Target IDs are typed.
2. Arbitrary paths cannot create targets.
3. Platform owns Android path knowledge.
4. Domain never hardcodes Android storage layout.
5. Unknown user state is conservative.
6. CE lock is never bypassed.
7. Shared storage is not cache by default.
8. External storage is opt-in/unsupported by default.
9. Package identity and filesystem identity remain separate.
10. Target roots are trusted boundaries.
11. Root identity is captured and revalidated.
12. Catalog snapshots are immutable.
13. Catalog generation is explicit.
14. Package/user races are expected.
15. One unavailable target does not kill the whole job.
16. SELinux cannot be bypassed by the daemon.
17. Android API level is not treated as kernel capability.
18. Actual capabilities are detected.
19. Catalog creation is read-only.
20. Catalog never performs destructive operations.
```

## Tahap selanjutnya: `app/` + orchestration

Setelah `config` dan `platform` selesai, kita sudah punya hampir semua **primitive keamanan**. Berikutnya kita perlu membangun lapisan yang menyatukan semuanya:

```text
src/app/
├── controller.rs
├── daemon.rs
├── commands.rs
└── lifecycle.rs
```

Di sana kita akan desain **`ApplicationController` sebagai satu-satunya orchestration layer**, termasuk alur persis:

```text
IPC Request
   ↓
Authorization
   ↓
Create Job
   ↓
Config Snapshot
   ↓
Platform Snapshot
   ↓
Readiness
   ↓
Scanner
   ↓
Safety
   ↓
Policy
   ↓
Planner
   ↓
Authorization final
   ↓
AuthorizedPlan
   ↓
Executor
   ↓
Verifier
   ↓
Report
   ↓
Scheduler
```

dan yang paling penting: **bagaimana memastikan tidak ada jalur alternatif dari CLI/IPC yang bisa langsung mencapai `Executor`.**
