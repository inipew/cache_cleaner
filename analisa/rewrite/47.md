47.md — Platform Abstraction, Android Platform Adapter, Linux Capability Detection, Storage State, Permission Boundary, and Platform Snapshot Contract

Tujuan

Dokumen ini mendefinisikan boundary antara cleanup engine dengan Android/Linux sebagai operating environment.

Platform Layer bertugas menyediakan fakta tentang sistem.

Platform Layer bukan:

```
cleanup engine
policy engine
scanner
executor
authorization layer
```

Platform Layer menyediakan:

```
device state
user state
package state
storage state
mount information
filesystem capability
kernel capability
Android capability
permission state
SELinux-related constraints
runtime readiness facts
```

Semua fakta tersebut dikumpulkan menjadi immutable:

```
PlatformSnapshot
```

1. Prinsip Utama

Domain tidak boleh mengetahui detail Android/Linux.

Dilarang:

```
Domain -> /data/user/0
Domain -> /proc
Domain -> /sys
Domain -> Android framework API
Domain -> ioctl
Domain -> SELinux syscall/detail
```

Sebaliknya:

```
Android/Linux
    │
    ▼
Platform Adapter
    │
    ▼
PlatformSnapshot
    │
    ▼
Domain / Scheduler / Policy / Safety
```

2. Platform Adapter

Platform Adapter adalah implementation boundary.

Contoh:

```
AndroidPlatformAdapter
LinuxPlatformAdapter
FilesystemPlatformAdapter
KernelPlatformAdapter

```

3. Interface Layer

Domain hanya mengenal interface:

```

```

bukan:


Dependency harus:

```

   │
   ▼

   │
   ▼

   │

```

5. Domain Purity

Domain tidak boleh import:

```
libc
nix

```

Detail tersebut berada di adapter.

6. PlatformSnapshot

PlatformSnapshot adalah immutable snapshot dari kondisi platform pada waktu tertentu.

Contoh konseptual:

```
PlatformSnapshot {
    generation
    timestamp
    android
    kernel
    storage
    users
    packages
    mounts
    capabilities
    security
    readiness
}
```

7. PlatformGeneration

Setiap snapshot memiliki:

```
PlatformGeneration
```

Contoh:

```
generation = 42
```

Jika kondisi platform berubah secara material:

```
generation = 43
```

8. Generation Purpose

Generation digunakan untuk mendeteksi stale decision.

Contoh:

```
Scan
   │
   ▼
PlatformGeneration = 42
   │
   ▼
Storage change
   │
   ▼
PlatformGeneration = 43
   │
   ▼
Old plan = STALE
```

9. Snapshot Tidak Mutable

Tidak boleh:

```
snapshot.storage.locked = false
```

Setelah dibuat:

```
PlatformSnapshot immutable
```

10. Snapshot Consistency

Semua data dalam snapshot harus memiliki consistency boundary.

Contoh:

```
package state
user state
storage state
mount state
```

harus berasal dari observasi yang dapat dipertanggungjawabkan pada generation yang sama.

11. Snapshot Is Not Eternal Truth

PlatformSnapshot bukan representasi permanen sistem.

Ia hanya:

```
observation at generation N
```

12. Freshness

Setiap consumer harus mengetahui:

```

snapshot_timestamp
freshness policy
```

Consumer tidak boleh menganggap snapshot selalu current.

Namun:

18. Kernel Capability

Kernel capability harus dideteksi secara aktual.

Contoh:

```

```

19. Capability Detection

Jangan:

```
if android_api >= X
    assume feature available
```

Lebih aman:

```
detect actual capability
```

20. Capability Snapshot

Contoh:

```

    openat2
```

21. Capability State

Capability harus mendukung:

```
Supported
Unsupported
Unknown
Restricted
```

22. Unknown Capability

Jika capability tidak diketahui:

```
jangan otomatis menggunakan feature sebagai mandatory dependency
```

dan:

```
jangan otomatis menganggap feature tersedia.
```

23. Capability Fallback

Contoh:

```
openat2 = Supported
```

gunakan hardened resolver.

Jika:

```
openat2 = Unsupported
```

gunakan fallback FD-relative implementation yang tetap memenuhi safety contract.

Jika:

```
openat2 = Unknown
```

pilih conservative path.

24. Capability Must Not Weaken Safety

Fallback tidak boleh berarti:

```
arbitrary path traversal
```

Jika safe implementation tidak tersedia:

```
operation tidak eligible untuk execution.
```

25. Kernel Adapter

Kernel adapter hanya mendeteksi capability dan menyediakan interface yang diperlukan.

Tidak boleh menjadi:


34. Package Race

Package dapat berubah selama cleanup.

Contoh:

```
scan:
    package installed

execution:
    package removed
```

Result:

```
stale / already gone
```

Jangan menganggap kondisi lama masih valid.

35. Package Reinstall Race

Contoh:

```
com.example.app
    inode/object A
```

package dihapus

kemudian install ulang:

```
com.example.app
    inode/object B
```

Path atau package name sama.

Identity berbeda.

Old plan tidak boleh menghapus object B.

46. Mount Boundary

Policy tidak boleh memutuskan mount boundary.

Safety layer menggunakan fakta platform/filesystem.

Contoh:

```
TrustedRoot
    │
    ├── child A
    │
    └── mount B
```

Jika cross-mount tidak diizinkan:

```
child B = rejected
```

47. Bind Mount

Bind mount harus diperlakukan sebagai boundary-sensitive condition.

Jangan menganggap:

```
same path prefix
    ==
same storage object
```

48. Overlay Filesystem

Android dapat menggunakan layered/overlay filesystem.

Platform adapter harus mengungkapkan capability/facts yang relevan.

Safety tetap menentukan apakah traversal aman.

49. Read-Only Filesystem

Jika filesystem read-only:


51. Storage Readiness


53. No Automatic Path Rebinding

Jika mount berubah:

```

    !=

```


59. Capability ≠ Authorization


60. Capability ≠ Policy Allow

Policy dapat mengatakan:

```

```
