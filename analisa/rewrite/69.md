69.md — Scanner, Candidate Model, Traversal Semantics, Metadata, Streaming, Deduplication, Safety Handoff, and Scan Contract

Tujuan

Dokumen ini mendefinisikan scanner sebagai komponen yang mengubah TargetDescriptor menjadi immutable Candidate tanpa melakukan mutation dan tanpa membuat keputusan authorization.

Pipeline:

TargetCatalog → Scanner → CandidateSet/stream → Policy → Planner

Scanner bertugas menemukan fakta filesystem. Scanner tidak menghapus, tidak mengotorisasi, dan tidak mengubah target.

1. Candidate Bukan Operation

Candidate adalah hasil observasi.
Operation adalah keputusan planner.

2. Candidate Bukan Authorization

Candidate yang memenuhi kriteria cache tidak berarti boleh dihapus.

3. Candidate Identity

Candidate harus mempunyai typed identity/reference yang memungkinkan revalidation.

4. Candidate Minimal Model

```rust
pub struct Candidate {
    pub id: CandidateId,
    pub target_id: TargetId,
    pub relative_path: RelativePath,
    pub kind: CandidateKind,
    pub metadata: CandidateMetadata,
    pub observed: ObservationIdentity,
    pub catalog_generation: CatalogGeneration,
}
```

5. CandidateId

CandidateId harus deterministic terhadap identity yang relevan dalam satu snapshot atau diberi unique observation identity.

6. Candidate Path

Simpan relative path terhadap TrustedRoot jika target rooted.

7. Raw Absolute Path

Absolute path tidak boleh menjadi satu-satunya reference candidate.

8. CandidateKind

Gunakan enum, misalnya:

- File
- Directory
- Symlink
- Other

9. Cache Semantics

`CandidateKind` filesystem type tidak sama dengan cache classification.

10. Classification Metadata

Candidate dapat mempunyai semantic hints seperti:

- age
- size
- extension
- package scope
- cache class

Namun hints tidak menjadi authority.

11. Scanner Read-only

Scanner tidak boleh melakukan destructive mutation.

12. Metadata Read Errors

Metadata error harus menjadi explicit scan result, bukan dipaksa menjadi zero/default.

13. Broken Symlink

Broken symlink harus explicit dan default tidak executable.

14. Symlink Policy

Scanner harus mencatat symlink sebagai symlink jika tidak diikuti oleh traversal policy.

15. Symlink Traversal

Default scanner harus tidak mengikuti symlink keluar dari TrustedRoot.

16. Mount Boundary

Scanner harus menghormati target mount boundary.

17. Cross Filesystem

Traversal lintas filesystem hanya jika TargetDescriptor secara eksplisit mengizinkannya.

18. Permission Denied

Permission denied pada subtree tidak boleh dianggap empty subtree.

19. Partial Scan

Scan dapat menghasilkan partial result, tetapi status partial harus explicit.

20. ScanResult

Recommended:

```rust
pub enum ScanStatus {
    Complete,
    Partial,
    Failed,
}
```

21. Partial Candidate Safety

Candidate dari partial scan tidak boleh mendapatkan privilege tambahan.

22. Scan Provenance

ScanResult harus mengikat:

- JobId
- TargetId
- CatalogGeneration
- scan start/end monotonic time
- scanner version
- status

23. Deterministic Traversal

Jika filesystem state sama, ordering harus deterministic atau CandidateSet harus di-sort sebelum planning.

24. Stable Ordering

Gunakan relative path ordering dengan comparator yang jelas.

25. Locale

Jangan gunakan locale-dependent ordering.

26. Case Sensitivity

Scanner harus mengikuti filesystem semantics, bukan asumsi host locale.

27. Path Length

Path component dan total path length harus bounded.

28. Entry Count Limit

Jumlah entry scan harus mempunyai limit.

29. Byte Budget

Scanner dapat memiliki metadata/read budget.

30. Time Budget

Scan harus mempunyai deadline/budget.

31. Cancellation

Scanner harus cooperative cancellation-aware.

32. Cancellation Point

Cancellation diperiksa setidaknya setiap batch entry dan operasi I/O yang dapat lama.

33. No Unbounded Directory Read

Scanner tidak boleh menahan jutaan entry dalam memory tanpa budget.

34. Streaming

Untuk target besar, scanner sebaiknya mengeluarkan Candidate secara streaming/bounded batches.

35. Backpressure

Consumer lambat tidak boleh membuat producer tidak terbatas menumpuk Candidate.

36. Candidate Batch

Batch harus bounded by count dan/atau bytes.

37. CandidateSet

Jika materialization diperlukan planner, gunakan bounded immutable collection.

38. Deduplication

Candidate duplicate harus dihilangkan berdasarkan identity yang tepat.

39. Hardlink

Hardlink bukan otomatis duplicate semantic target. Identity inode/device harus dipertimbangkan sesuai operation semantics.

40. File Identity

ObservationIdentity sebaiknya menyimpan device/inode atau equivalent identity jika platform menyediakan.

41. Size

Size adalah observed fact, bukan guarantee pada execution.

42. mtime

mtime adalah observed fact dan dapat berubah setelah scan.

43. ctime

ctime dapat digunakan sebagai signal tetapi bukan cache authority.

44. atime

atime harus dianggap optional dan filesystem-dependent.

45. Birth Time

Jangan mengandalkan creation time sebagai invariant portable.

46. File Type

Gunakan filesystem stat type, bukan extension.

47. Extension

Extension hanya hint untuk policy/classification.

48. Hidden Files

Hidden status adalah metadata, bukan automatic delete permission.

49. Empty Directory

Directory candidate hanya boleh dibuat jika policy/operation memang mendukung directory cleanup.

50. Directory Recursion

Recursive delete tidak boleh diputuskan scanner.

51. Candidate Parent/Child

Planner harus menangani dependency parent-child; scanner hanya melaporkan keduanya.

52. Candidate Package Scope

Jika scanner mengetahui package scope, scope harus typed dan berasal dari target descriptor/discovery.

53. Candidate Outside Target

Candidate di luar TrustedRoot harus tidak dihasilkan.

54. Path Escape

`..`, encoded traversal, separator tricks, dan equivalent forms harus dinormalisasi/ditolak sesuai RelativePath contract.

55. NUL

Path component dengan NUL harus ditolak.

56. Invalid UTF-8

Filesystem name tidak selalu UTF-8. Domain harus menentukan apakah menggunakan OsString/bytes atau lossy representation untuk display.

57. Display Name

Display name tidak boleh digunakan sebagai identity.

58. Unicode Normalization

Jangan normalisasi filesystem identity secara lossy.

59. Permission Metadata

Permission/ownership dapat dicatat sebagai observation jika dibutuhkan policy.

60. Ownership

UID/GID adalah observed metadata, bukan automatic authorization.

61. Mode Bits

Mode bits harus dibaca melalui platform abstraction.

62. Special Files

Device nodes, sockets, FIFOs, dan special files default harus non-executable candidates.

63. Proc/Sys

Virtual filesystems harus explicit target policy, bukan scanner generic.

64. `/proc`/`/sys`

Scanner cache tidak boleh memperlakukan virtual filesystem sebagai normal cache target.

65. Android Package Cache

Package cache classification harus berasal dari TargetDescriptor/package scope dan platform semantics, bukan substring path semata.

66. OEM Cache

OEM-specific cache rules harus isolated dalam target discovery/classifier adapter.

67. Exclusion

Exclusion rules harus typed/configured melalui Policy layer.

68. Scanner vs Policy

Scanner boleh mengumpulkan age/size/type.
Policy memutuskan apakah fakta tersebut memenuhi policy.

69. Scanner vs Safety

Scanner melakukan basic traversal safety, tetapi final filesystem safety tetap dilakukan Safety Gate.

70. TOCTOU

Candidate observation selalu potentially stale.

71. ObservationIdentity

Candidate harus menyimpan identity yang bisa dibandingkan saat revalidation.

72. Revalidation

Sebelum mutation, Executor/Safety harus memastikan candidate masih menunjuk object yang sama atau operation harus stale.

73. File Replacement

Jika file diganti setelah scan, path equality tidak cukup.

74. Rename

Rename setelah scan harus menyebabkan stale candidate jika identity/path binding operation tidak lagi cocok.

75. Delete Before Execute

Jika candidate sudah hilang, operation dapat dianggap already satisfied atau stale sesuai idempotency semantics; tidak boleh dianggap berhasil tanpa klasifikasi.

76. Unknown Stat

Jika identity tidak dapat dibaca, jangan downgrade menjadi path-only safety.

77. Scan Errors

Error harus typed:

- PermissionDenied
- NotFound
- Io
- InvalidPath
- ResourceLimit
- Cancelled
- Timeout
- Unsupported

78. Error Aggregation

Multiple subtree errors harus dapat dilaporkan tanpa menghentikan seluruh scan jika policy mengizinkan partial scan.

79. Fatal Errors

Root identity failure, safety boundary failure, atau catalog mismatch harus fatal untuk target tersebut.

80. Scan Retry

Transient read errors dapat retry bounded jika platform adapter menyatakan safe.

81. No Mutation Retry

Scanner retry tidak boleh memicu mutation.

82. Scan Snapshot

Scanner dapat mengambil filesystem observation snapshot, tetapi tidak boleh mengklaim atomic filesystem snapshot kecuali platform benar-benar menyediakan.

83. Concurrent Changes

Filesystem dapat berubah selama scan.

Candidate harus diperlakukan sebagai observation, bukan snapshot guarantee.

84. Generation Binding

Candidate membawa CatalogGeneration yang digunakan saat discovery.

85. Config Binding

Jika classification dipengaruhi config, Candidate/ScanResult juga harus menyimpan ConfigGeneration.

86. Configuration Change

Config change selama scan tidak boleh membuat candidate otomatis mengikuti config baru.

87. Plan Binding

Planner harus menentukan apakah scan snapshot masih kompatibel dengan current ConfigGeneration.

88. Scan Resume

Resume scan hanya boleh menggunakan checkpoint yang identity-bound dan generation-aware.

89. Checkpoint

Checkpoint tidak boleh hanya berupa path string jika path reuse dapat terjadi.

90. Worker Isolation

Scanner berjalan dalam worker execution budget yang dibatasi ResourceManager.

91. Memory Budget

Candidate buffering harus mengikuti reservation/budget.

92. CPU Budget

Deep metadata/classification harus mempunyai CPU budget bila diperlukan.

93. I/O Budget

Scanner harus menghormati I/O concurrency limits.

94. Priority

Priority memengaruhi scheduling, bukan safety.

95. Fairness

Satu target besar tidak boleh starvation terhadap target lain jika scheduler mendukung fairness.

96. Candidate Size Accounting

Ukuran candidate set harus dipantau agar planner tidak menerima unbounded input.

97. Large Directory

Directory dengan entry sangat besar harus diproses streaming.

98. Huge File

Ukuran file harus menggunakan checked arithmetic.

99. Overflow

Aggregate size overflow harus menghasilkan error, bukan wrap-around.

100. Symlink Loop

Traversal harus mempunyai loop detection/visited identity atau tidak mengikuti symlink.

101. Hardlink Loop

Directory hardlink semantics harus mengikuti filesystem; jangan berasumsi tree selalu acyclic tanpa validation.

102. Mount Loop

Mount traversal harus bounded dan identity-aware.

103. Device Boundary

Scanner tidak boleh membaca device content sebagai regular file candidate.

104. Candidate Classification

Classification harus deterministic dari observed facts + target semantics.

105. No Hidden Authority

Nama file seperti `cache`, `.cache`, `tmp`, atau extension tertentu tidak boleh otomatis memberi destructive classification.

106. Cache Evidence

Cache classification dapat memerlukan kombinasi target kind, path scope, age, metadata, dan platform rules.

107. Conservative Unknown

Jika classification tidak pasti, candidate harus `Unknown`/non-actionable.

108. Unknown != Safe

Unknown tidak berarti aman untuk dihapus.

109. Candidate Confidence

Jika classifier memakai confidence, low confidence harus fail-closed untuk destructive operations.

110. Candidate Provenance

Candidate harus dapat ditelusuri ke TargetId dan scan snapshot.

111. Audit

Scan event harus dapat mencatat jumlah discovered, accepted, rejected, errors, partial status, dan bytes observed.

112. Privacy

Logging path/package harus mengikuti redaction policy.

113. No Sensitive Dump

Jangan dump seluruh filesystem names ke log default.

114. Candidate Serialization

IPC/persistence Candidate harus versioned DTO.

115. Domain vs DTO

DTO tidak boleh digunakan langsung sebagai authority object.

116. Candidate Mutation

Candidate tidak boleh mempunyai method yang melakukan delete/mutation.

117. Candidate to Operation

Hanya Planner yang boleh mengubah Candidate menjadi PlannedOperation.

118. Candidate Eligibility

Policy menghasilkan eligibility decision terpisah dari Candidate.

119. Policy Re-evaluation

Planner dapat melakukan policy check ulang jika candidate observation sudah tua.

120. Safety Handoff

Candidate harus menyerahkan observation identity kepada Safety Gate.

121. Safety Failure

Safety failure tidak boleh diubah menjadi policy skip secara diam-diam; result harus explicit.

122. Partial Job

Jika sebagian candidate scan gagal, JobResult harus membedakan completed scan, partial scan, dan skipped candidates.

123. Scan Cancellation

Cancellation menghasilkan explicit scan status dan tidak memalsukan CandidateSet complete.

124. Timeout

Timeout menghasilkan incomplete/failed scan sesuai boundary, bukan successful scan.

125. Testability

Scanner harus menggunakan filesystem abstraction agar dapat diuji tanpa device nyata.

126. Fake Filesystem

Test fixture harus mendukung replacement, symlink, mount boundary, permission error, dan concurrent mutation simulation.

127. Property Testing

Property penting:

- candidate selalu berada di target root
- no path escape
- no mutation during scan
- deterministic ordering
- bounded memory
- identity preserved

128. Fuzzing

Fuzz relative paths, malformed names, deep trees, huge metadata, symlink graphs, and target descriptors.

129. Race Testing

Simulasikan rename/delete/recreate antara scan dan execution.

130. Definition of Done

Scanner production-ready jika:

- read-only
- streaming/bounded
- cancellation-aware
- timeout-aware
- generation-bound
- identity-aware
- symlink policy explicit
- mount boundary explicit
- errors typed
- partial result explicit
- deterministic
- no raw path authority
- no hard-coded destructive rules
- candidate immutable
- final safety handoff tersedia
- fuzz/property/race tests tersedia

131. Final Invariants

1. Scanner hanya mengobservasi.
2. Candidate bukan operation.
3. Candidate bukan authorization.
4. Absolute path bukan identity.
5. Relative path harus berada di TrustedRoot.
6. Candidate identity harus dapat direvalidasi.
7. Scanner tidak boleh mengikuti symlink secara unsafe.
8. Cross-mount traversal harus explicit.
9. Permission error bukan empty result.
10. Partial scan harus explicit.
11. Unknown tidak sama dengan safe.
12. Observation tidak menjamin execution state.
13. CatalogGeneration harus dipertahankan.
14. ConfigGeneration harus dipertahankan jika classification bergantung config.
15. Candidate buffering harus bounded.
16. Aggregate arithmetic harus checked.
17. Mutation tidak boleh terjadi di scanner.
18. Executor harus melakukan final safety validation.
19. Candidate replacement/reuse harus terdeteksi melalui identity.
20. Candidate provenance harus dapat diaudit.
