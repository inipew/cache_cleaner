# 2. `walk_directory()` harus punya state

Jangan recursive function sederhana:

```rust
fn walk(path: PathBuf) {
    for entry in read_dir(path) {
        walk(entry);
    }
}
```

Untuk cleaner privileged saya lebih suka:

```rust
pub struct Walker {
    stack: Vec<DirectoryFrame>,
}
```

Kemudian:

```rust
while let Some(frame) = stack.pop() {
    process_frame(frame)?;
}
```

Keuntungannya:

* tidak bergantung stack call depth
* cancellation mudah
* bounded memory lebih mudah
* error per-directory bisa dipisahkan
* progress tracking lebih mudah

## Dan ada satu hal lagi yang belum kita bahas: apa sebenarnya yang *harus* dibersihkan?

Ini justru harus kita bahas **sebelum function implementation**.

Kita perlu membuat **Target Catalog**:

```text
TARGET CATALOG
│
├── App Cache
│   ├── user/0/.../cache
│   ├── user/10/.../cache
│   └── user_de/.../cache
│
├── Code Cache
│
├── Package Manager Cache
│
├── Framework Cache
│
├── Temporary
│
├── System Cache
│
├── Dalvik/ART
│
├── Compiled Artifacts
│
└── NEVER TOUCH
    ├── databases
    ├── shared_prefs
    ├── files
    ├── no_backup
    ├── app native libs
    └── unknown
```

Karena dari sinilah `classifier`, `policy`, `planner`, dan `executor` semuanya berasal.

Repository saat ini memang sudah mengiklankan standard clean sebagai app cache dengan minimum age 24 jam dan deep clean sebagai tambahan FITRIM/ZRAM. ([GitHub][2]) **Tetapi untuk rewrite total, saya ingin kita tidak menerima daftar target itu begitu saja—kita audit satu per satu dan menentukan apakah masing-masing target benar-benar aman, berguna, deprecated, atau sebaiknya dihapus dari scope.**

Jadi menurut saya **pembahasan berikutnya yang paling fundamental adalah membuat `Target Catalog + Function Catalog`**. Setelah itu baru kita bisa mendesain `struct/enum/signature` setiap fungsi secara konkret dan akhirnya menghasilkan blueprint yang hampir bisa langsung diterjemahkan menjadi source code.
