# 81.md — Android Platform Adapter, Kernel/Filesystem Boundary, Capability Discovery, Mount Identity, Package/User Resolution, and Revalidation Contract

## Tujuan

Android-specific behavior harus dipisahkan dari generic cache-cleaning core. Core tidak boleh menebak layout Android, memanggil shell command secara ad-hoc, atau menganggap satu path berlaku untuk semua device/OEM.

Arsitektur target:

```text
Android OS / Kernel
        │
        ▼
Platform Adapter
        │
        ├── Device/Build Identity
        ├── Mount Discovery
        ├── Package/User Discovery
        ├── Target Discovery
        ├── Filesystem Capabilities
        ├── Privilege/Capability Detection
        ├── Runtime Sensors
        └── Revalidation
        │
        ▼
Generic Core
```

## 1. Adapter Bukan Business Logic

Android adapter hanya menerjemahkan platform facts menjadi typed domain facts.

Ia tidak boleh mengambil keputusan policy seperti "hapus cache jika > X".

## 2. Platform Facts

Adapter boleh menyediakan:

- Android release/API level
- build fingerprint/version
- ABI
- kernel information
- mount topology
- filesystem information
- package/user information
- available kernel interfaces
- privilege state
- filesystem operation capabilities

## 3. Typed PlatformIdentity

Jangan expose kumpulan `String` mentah sebagai platform identity.

Gunakan typed value objects untuk API level, ABI, device/build identity, dan user/package identity.

## 4. API Level

API level harus typed dan validated.

Nilai invalid/overflow tidak boleh diterima sebagai supported Android version.

## 5. Build Identity

Build fingerprint dapat digunakan untuk diagnostics dan compatibility selection.

Ia bukan authorization.

## 6. OEM Detection

OEM/model/build detection hanya boleh mempengaruhi discovery/compatibility behavior yang terdokumentasi.

Jangan menggunakan substring model sebagai safety decision tanpa explicit rule.

## 7. Root Privilege

Root status harus direpresentasikan sebagai capability observation.

`uid == 0` tidak otomatis berarti seluruh filesystem operation berhasil.

## 8. Effective Capability

Capability harus diuji dari operation yang relevan, bukan hanya dari privilege label.

## 9. SELinux

SELinux enforcement/status dapat mempengaruhi effective capability.

Adapter harus membedakan "root" dari "operation actually permitted".

## 10. Mount Discovery

Mount topology harus didapat dari authoritative kernel/platform source yang tersedia.

Parsing `/proc/mounts`, `/proc/self/mountinfo`, atau equivalent harus berada di adapter.

## 11. MountInfo Parser

Parser harus typed, bounded, dan tahan malformed records.

## 12. Mount Identity

Mount record harus menyediakan identity yang dapat digunakan untuk revalidation jika kernel menyediakan informasi tersebut.

## 13. Device Identity

Major/minor device information harus typed.

## 14. Filesystem Type

Filesystem type harus typed/normalized.

Contoh:

- ext4
- f2fs
- erofs
- overlay
- tmpfs
- fuse
- unknown

## 15. Unknown Filesystem

Unknown filesystem tidak boleh diasumsikan aman untuk mutation.

## 16. Read-Only Detection

Mount flags harus dipetakan ke capability.

Read-only berarti mutation capability tidak tersedia.

## 17. Mount Boundary

Adapter harus dapat menjelaskan mount boundary untuk TargetCatalog/Safety.

## 18. Bind Mount

Bind mount harus dapat dibedakan dari sekadar lexical path bila kernel metadata memungkinkan.

## 19. Overlay

Overlay filesystem harus mempunyai explicit classification.

Jangan menjalankan cleanup berdasarkan lower/upper path assumptions yang tidak tervalidasi.

## 20. FUSE

FUSE/remote-like filesystems memerlukan capability classification khusus.

## 21. Package Manager Boundary

Package identity sebaiknya berasal dari Android package management source, bukan directory enumeration saja.

## 22. PackageName

Package name harus divalidasi sebagai typed PackageName.

## 23. Package Path

Package path yang diperoleh dari package manager tetap harus melewati filesystem safety validation.

## 24. Package UID

UID/user mapping harus dipertimbangkan saat target package-specific.

## 25. Multi-user

Android multi-user harus menjadi first-class concern.

Jangan mengasumsikan semua package berada pada user 0.

## 26. UserId

UserId harus typed dan bounded.

## 27. User Isolation

Discovery untuk user A tidak boleh menghasilkan target user B.

## 28. Work Profile

Work profile/secondary profile harus diperlakukan sebagai distinct user scope bila platform exposes it.

## 29. Package Reinstall

Package name yang sama setelah reinstall tidak otomatis berarti target filesystem identity sama.

## 30. Package Lifecycle

Install/uninstall/replace events adalah refresh hints.

Catalog harus direbuild/revalidate.

## 31. Android Cache Semantics

Target discovery harus berdasarkan semantic cache category, bukan sekadar nama directory `cache`.

## 32. App Cache

App cache harus memiliki package/user binding dan root identity.

## 33. Code Cache

Code cache harus mempunyai TargetKind sendiri jika semantics cleanup berbeda.

## 34. External Cache

External/shared cache harus mempunyai storage scope yang explicit.

## 35. Shared Storage

Shared storage bukan otomatis equivalent dengan app-private cache.

Policy harus membedakannya.

## 36. System Cache

System cache harus protected by default.

## 37. OEM Cache

OEM-specific cache target hanya boleh enabled jika discovery adapter dapat membuktikan target semantics.

## 38. Unknown OEM Directory

Unknown directory name tidak boleh diperlakukan sebagai cache hanya karena namanya mengandung `cache`.

## 39. Static Compatibility Paths

Legacy known paths boleh digunakan sebagai discovery hints.

Hasilnya tetap harus diverifikasi.

## 40. Shell Command Boundary

Generic core tidak boleh menjalankan `sh -c` untuk operasi platform.

Adapter dapat menggunakan native syscalls/APIs atau tightly controlled commands jika memang tidak tersedia native interface.

## 41. Argument Safety

Jika command unavoidable, arguments harus structured dan tidak melalui shell interpolation.

## 42. Command Output

Output command harus diparse sebagai untrusted platform input.

## 43. Timeout

Platform calls yang dapat hang harus bounded.

## 44. Cancellation

Long-running discovery harus mendukung cancellation jika API memungkinkan.

## 45. Resource Limits

Adapter harus membatasi jumlah package, mount, record, path length, metadata size, dan traversal depth.

## 46. Path Encoding

Path dari kernel/package manager harus diperlakukan sebagai bytes/OS strings sesuai platform, bukan dipaksa UTF-8 secara blind.

## 47. Invalid UTF-8

Invalid UTF-8 harus tetap dapat direpresentasikan atau ditolak secara explicit; tidak boleh menjadi silent replacement.

## 48. `/proc` Semantics

Procfs data adalah snapshot dan dapat berubah segera setelah read.

## 49. Sysfs Semantics

Sysfs data harus dianggap dynamic platform state.

## 50. Capability Snapshot

Adapter sebaiknya menghasilkan immutable `PlatformSnapshot`.

```rust
pub struct PlatformSnapshot {
    pub identity: PlatformIdentity,
    pub mounts: Arc<[MountDescriptor]>,
    pub capabilities: PlatformCapabilities,
    pub users: Arc<[UserDescriptor]>,
    pub packages: Arc<[PackageDescriptor]>,
}
```

## 51. Snapshot Generation

Platform snapshot dapat mempunyai generation/revision yang berbeda dari CatalogGeneration.

## 52. Catalog Dependency

TargetCatalog menggunakan PlatformSnapshot sebagai input, bukan memanggil adapter arbitrarily sepanjang planning.

## 53. Refresh

Platform snapshot harus dapat di-refresh setelah topology/event changes.

## 54. Capability Downgrade

Jika capability hilang, current catalog harus direvalidasi.

## 55. Capability Upgrade

Capability baru tidak otomatis memperluas existing Authorization.

## 56. Mount Disappearance

Unmount harus membuat target unavailable/stale.

## 57. Mount Replacement

Mount baru pada path yang sama harus dianggap potentially different identity.

## 58. Device Reuse

Device major/minor reuse tidak cukup sebagai sole identity.

## 59. Filesystem UUID

Jika tersedia, filesystem UUID dapat menjadi identity component.

## 60. Root Inode

Root inode/device dapat menjadi additional identity evidence.

## 61. Identity Confidence

Jika platform tidak menyediakan identity yang cukup kuat, adapter harus menandai limitations daripada membuat false certainty.

## 62. Conservative Revalidation

Insufficient identity evidence harus menghasilkan stale/blocked state untuk destructive operation bila equivalence tidak dapat dibuktikan.

## 63. Filesystem Feature Detection

Filesystem-specific capabilities harus explicit.

## 64. F2FS

F2FS-specific maintenance operations harus berada pada adapter/maintenance capability layer, bukan generic delete executor.

## 65. TRIM

TRIM capability harus dideteksi sebelum request dikirim.

## 66. ZRAM

ZRAM maintenance adalah platform maintenance operation, bukan cache deletion.

## 67. Sysfs Maintenance

Sysfs writes harus mempunyai typed operation dan strict allowlist.

## 68. Procfs Maintenance

Procfs writes harus explicit capability-gated dan tidak boleh diperlakukan sebagai generic file mutation.

## 69. Kernel Interface Versioning

Kernel interface availability dapat berbeda antar Android/OEM.

Adapter harus feature-detect.

## 70. No Blind Kernel Assumptions

Jangan menganggap path sysfs/procfs selalu ada.

## 71. Permission Failure

Permission denied harus menjadi typed capability/operation failure, bukan generic empty result.

## 72. ENOENT

ENOENT pada dynamic platform source harus dibedakan antara unsupported, disappeared, dan malformed source bila dapat diketahui.

## 73. EACCES

EACCES harus mempertahankan provenance bahwa operation ditolak permission layer.

## 74. EPERM

EPERM harus dibedakan dari missing path.

## 75. EBUSY

Busy filesystem/object harus menghasilkan retryable or blocked classification sesuai operation.

## 76. EIO

I/O errors pada discovery/revalidation harus dianggap serious platform failure.

## 77. Mount Event

Mount/unmount/change events adalah hints; refresh melakukan authoritative rediscovery.

## 78. Package Event

Package events harus memicu catalog refresh/debounce.

## 79. User Event

User lifecycle events harus memicu scope reconciliation.

## 80. Boot

Startup harus melakukan full platform discovery sebelum daemon menerima destructive work.

## 81. Early Boot

Jika platform belum stable, daemon dapat berada dalam degraded/recovery state.

## 82. Storage Not Ready

Storage unavailable bukan equivalent dengan empty storage.

## 83. Permission Not Ready

Temporary permission initialization harus dibedakan dari permanent denial.

## 84. Android Scoped Storage

Adapter harus mempertimbangkan scoped-storage semantics dan privilege context.

## 85. Rooted Device Variance

Rooted Android devices tidak mempunyai satu universal root behavior.

Magisk/su implementation, SELinux, mount namespace, dan policy dapat berbeda.

## 86. Mount Namespace

Adapter harus mengetahui namespace tempat daemon berjalan jika relevan.

Melihat mount topology namespace lain secara tidak sengaja dapat menghasilkan false target identity.

## 87. Namespace Identity

Mount identity harus terkait dengan namespace context bila diperlukan.

## 88. Daemon Context

Target path harus direvalidasi dalam namespace tempat Executor akan melakukan mutation.

## 89. Chroot/Container

Jika daemon berjalan dalam altered root/chroot/container, host path assumptions tidak boleh digunakan.

## 90. Working Directory

Relative paths dari current working directory tidak boleh menjadi target authority.

## 91. File Descriptor Context

Final safety resolution sebaiknya menggunakan FD-relative operations ketika platform supports it.

## 92. `openat` Family

FD-relative resolution preferred untuk reducing TOCTOU.

## 93. `O_NOFOLLOW`

Jika tersedia/relevan, symlink avoidance harus digunakan untuk security-sensitive resolution.

## 94. `openat2`

Jika platform/kernel supports it, stronger resolution constraints dapat digunakan.

## 95. Android Kernel Compatibility

Jangan membuat `openat2` mandatory jika target devices tidak menjamin availability.

Gunakan capability-based fallback dengan safety equivalence yang explicit.

## 96. Fallback Safety

Fallback yang lebih lemah tidak boleh diam-diam diperlakukan sama dengan strongest implementation.

## 97. Adapter Error Model

Gunakan typed errors dengan provenance:

- Unsupported
- PermissionDenied
- NotFound
- TemporarilyUnavailable
- IdentityMismatch
- InvalidData
- Io
- Timeout
- Cancelled

## 98. Error Preservation

Jangan mengubah semua adapter errors menjadi `anyhow::Error` terlalu awal jika caller membutuhkan classification.

## 99. Audit Metadata

Platform decisions harus dapat direkonstruksi dari snapshot/generation, bukan dari mutable globals.

## 100. Testing Adapter

Wajib memiliki fake platform backend.

## 101. Fake Mount Table

Test mount replacement, bind mount, readonly, overlay, missing mount.

## 102. Fake Package Manager

Test multi-user, uninstall, reinstall, UID change, malformed package data.

## 103. Fake Capability Provider

Test capability downgrade/upgrade dan permission failures.

## 104. Snapshot Consistency

Pastikan catalog dibuat dari coherent platform snapshot.

## 105. Race Test

Simulasikan mount change antara discovery, planning, dan execution.

## 106. Property Test

Malformed mount/package records tidak boleh menghasilkan executable target secara permissive.

## 107. Fuzz Test

Fuzz parsers untuk `/proc`/mount/package metadata.

## 108. OEM Matrix

Fixture beberapa layout/OEM variants yang diketahui.

## 109. Unknown OEM

Unknown OEM harus degraded gracefully tanpa broad deletion fallback.

## 110. Definition of Done

Android Platform Adapter production-ready jika:

- generic core bebas Android path assumptions
- platform facts typed
- mount/package/user discovery terpisah
- capability detection explicit
- mount identity tersedia/revalidated
- readonly state enforced
- namespace context diperhatikan
- package/user scope aman
- OEM variance tidak menghasilkan broad matching
- shell boundary terkendali
- parser bounded
- errors typed
- dynamic source dianggap snapshot
- refresh atomic
- capability changes memicu revalidation
- filesystem-specific maintenance terpisah
- fake platform tests tersedia
- fuzz/property/race tests tersedia

## 111. Final Invariants

1. Android adapter menerjemahkan platform facts; ia bukan policy engine.
2. Raw path bukan target authority.
3. Root privilege bukan jaminan operation success.
4. Capability bukan authorization.
5. Unknown filesystem tidak boleh diasumsikan aman.
6. Read-only mount tidak memiliki mutation capability.
7. Mount path yang sama tidak membuktikan mount identity yang sama.
8. Package name yang sama tidak membuktikan filesystem identity yang sama.
9. User scope selalu explicit.
10. OEM-specific path tidak boleh menjadi broad deletion rule.
11. Platform snapshots immutable selama satu decision cycle.
12. Dynamic platform events adalah refresh hints.
13. Discovery failure tidak boleh diperlakukan sebagai empty storage.
14. Identity insufficiency harus fail-safe.
15. Final mutation context harus direvalidasi dalam daemon's actual namespace.
16. Generic core tidak boleh menjalankan shell command untuk business logic.
17. Sysfs/procfs maintenance mempunyai capability boundary sendiri.
18. Adapter errors mempertahankan semantic classification.
19. Capability downgrade tidak boleh memperluas existing authorization.
20. Android platform assumptions harus terisolasi di adapter.
