70.md — Safety Implementation, Trusted Resolution, Identity Revalidation, Mount Boundaries, Final Mutation Gate, and Fail-Closed Contract

Tujuan

Safety adalah security boundary yang memastikan candidate/path yang ditemukan sebelumnya masih merupakan object dan target yang memang diizinkan untuk disentuh saat mutation.

Pipeline:

TargetCatalog → Candidate → Policy → Plan → Authorization → Safety Gate → Executor

Safety bukan sekadar `is_path_allowed()`.

1. Safety Is Runtime Boundary

Safety harus berjalan dekat dengan mutation boundary.

2. Safety != Policy

Policy menjawab apakah operation diinginkan/diizinkan secara rules.
Safety menjawab apakah operation secara filesystem/runtime masih aman dilakukan.

3. Safety != Authorization

Authorization memberi capability untuk operation tertentu.
Safety memvalidasi object dan boundary.

4. TrustedRoot

TrustedRoot adalah root yang telah divalidasi dan menjadi boundary resolution.

5. Root Handle

Jika platform mendukung, root directory handle/FD lebih baik daripada raw absolute path.

6. FD-relative Resolution

Resolution candidate sebaiknya relatif terhadap trusted root menggunakan APIs seperti `openat`-style semantics bila tersedia.

7. No String Concatenation

Jangan membentuk path mutation dengan string concatenation.

8. RelativePath

Candidate path harus typed RelativePath yang telah dinormalisasi dan divalidasi.

9. Path Escape

`..`, repeated separators, absolute path injection, NUL, dan platform-specific traversal harus ditolak.

10. Canonicalization

Canonicalization tidak boleh digunakan sebagai satu-satunya safety primitive karena race dapat terjadi setelah canonicalization.

11. Identity Validation

Resolution harus menghasilkan object identity yang dapat dibandingkan dengan observation dari Candidate.

12. File Identity

Jika tersedia, gunakan device/inode atau equivalent filesystem identity.

13. Metadata Revalidation

Re-read metadata tepat sebelum mutation.

14. Candidate Observation

Candidate menyimpan observation identity, size, type, dan metadata relevan.

15. Size Change

Jika operation bergantung size, perubahan size dapat menyebabkan stale operation atau harus ditangani secara explicit.

16. Type Change

File menjadi directory/symlink atau sebaliknya harus selalu dianggap identity/type mismatch.

17. Replacement

Delete-and-recreate pada path yang sama tidak boleh dianggap object yang sama.

18. Rename

Rename dapat menyebabkan candidate stale jika path binding operation mensyaratkannya.

19. Symlink

Safety default tidak boleh mengikuti symlink untuk destructive target.

20. Symlink Final Component

Final path component yang menjadi symlink harus ditangani explicit dan default ditolak untuk destructive operation.

21. Intermediate Symlink

Intermediate component symlink harus ditolak atau di-resolve hanya jika safety contract secara eksplisit mendukungnya.

22. Mount Boundary

Safety harus memastikan resolved object tetap berada pada filesystem/mount boundary target.

23. Cross-Mount

Cross-mount traversal harus ditolak untuk target yang scoped ke mount.

24. Bind Mount

Bind mount harus diverifikasi berdasarkan mount/filesystem identity, bukan lexical path.

25. Overlay

Overlay semantics harus diperlakukan explicit; path identity tidak boleh dianggap setara dengan underlying storage object.

26. Read-only

Mutation pada read-only mount harus fail sebelum executor syscall destructive.

27. Filesystem Type

Jika target membatasi filesystem type, Safety harus memvalidasinya.

28. Storage Identity

Target storage identity harus cocok dengan descriptor/plan.

29. Device Identity

Device major/minor dapat menjadi check tambahan, bukan selalu satu-satunya identity.

30. Mount Identity

Mount ID atau equivalent kernel identity sebaiknya dipakai bila tersedia.

31. Root Identity

Trusted root harus direvalidasi sebelum mutation.

32. Root Replacement

Root yang diganti harus menghasilkan safety failure.

33. Permission Revalidation

Permission yang berubah dapat membuat authorization/capability stale.

34. Ownership

Ownership mismatch harus ditangani sesuai target safety contract.

35. Mode

Mode perubahan tidak boleh membuat operation lebih permissive.

36. Protected Root

Protected roots mempunyai explicit deny rules.

37. System Path

Generic delete capability tidak boleh membuka system path.

38. Parent Safety

Safety harus memastikan parent directory juga berada dalam boundary yang valid.

39. Deletion Semantics

Directory deletion membutuhkan safety proof terhadap seluruh subtree sesuai operation semantics.

40. Recursive Delete

Recursive delete tidak boleh mengandalkan satu path check.

41. Recurse-Then-Mutate

Setiap child mutation harus tetap mengikuti safety boundary.

42. Race During Recursion

Target dapat berubah antara enumeration dan child mutation.

Setiap mutation harus melakukan relevant revalidation.

43. No TOCTOU Illusion

Check-then-use dengan raw path tidak cukup.

44. Atomic OS Primitive

Gunakan OS primitive yang mengurangi race, misalnya dirfd-relative APIs, no-follow flags, and appropriate resolution constraints bila tersedia.

45. `O_NOFOLLOW`

Gunakan no-follow semantics pada operasi yang sesuai.

46. `openat2`-style Constraints

Linux implementation dapat memanfaatkan resolution flags seperti beneath/in-root/no-symlink bila tersedia melalui platform adapter.

47. Android Compatibility

Tidak semua kernel Android menyediakan primitive yang sama; adapter harus expose capability dan fallback yang fail-closed.

48. Fallback

Fallback yang lebih lemah tidak boleh diam-diam dianggap equivalent security.

49. Capability-aware Safety

Safety implementation harus mengetahui primitive kernel yang tersedia.

50. Final Safety Gate

Sebelum destructive syscall, jalankan final gate.

51. Gate Inputs

Minimal:

- JobId
- OperationId
- TargetId
- CatalogGeneration
- ConfigGeneration
- AuthorizationId
- candidate identity
- relative path
- expected type
- required capability

52. Gate Output

Gate harus menghasilkan immutable `SafetyProof` atau explicit denial.

53. SafetyProof

Proof hanya valid untuk operation context yang tepat.

54. No Proof Reuse

SafetyProof tidak boleh dipakai untuk operation/path lain.

55. Operation Binding

Proof harus mengikat OperationId atau equivalent unique operation identity.

56. Generation Binding

Proof harus mengikat target/config generation yang menjadi basis validation.

57. Expiration

Jika validation dapat menjadi stale karena waktu/resource conditions, proof harus mempunyai bounded lifetime/deadline.

58. Revalidation Immediately Before Mutation

Semakin destructive operation, semakin dekat safety check harus berada dengan mutation.

59. Authorization Before Safety

Authorization dan Safety dapat dilakukan berurutan sesuai architecture, tetapi Safety final gate harus tetap berada setelah semua planning/authorization decisions.

60. Safety Cannot Grant

Safety hanya menolak atau membuktikan runtime safety; tidak memberi authorization.

61. Policy Cannot Bypass

Policy `allow` tidak dapat bypass Safety.

62. Authorization Cannot Bypass

Authorization `allow` tidak dapat bypass Safety.

63. Force Flag

Force hanya dapat mengubah policy behavior jika secara eksplisit diizinkan; tidak boleh bypass filesystem safety invariants.

64. Root Handle Lifetime

Jika memakai dirfd, lifetime handle harus mencakup resolution/mutation sequence yang relevan.

65. FD Ownership

Owner FD harus jelas; tidak boleh closed/reused oleh component lain sebelum mutation.

66. FD Reuse

Raw integer FD tidak boleh menjadi identity setelah close/reuse.

67. Borrowed vs Owned

API harus membedakan borrowed dan owned file descriptors.

68. Close-on-exec

FD safety harus mempertimbangkan `O_CLOEXEC` bila subprocess dapat digunakan.

69. Directory Handle

Directory handle dapat menjadi anchor safety.

70. Target Root Handle

Idealnya TrustedRoot menyimpan opened directory handle atau safely reopenable identity-bound reference.

71. Reopen

Jika root harus dibuka ulang, identity harus dibandingkan sebelum digunakan.

72. Mount Change

Mount change harus invalidate affected catalog/plan/authorization contexts.

73. Mount Event

Mount events adalah trigger revalidation, bukan proof.

74. Storage Detach

Storage detach membuat affected operations unavailable/stale.

75. Storage Reattach

Reattach tidak otomatis valid tanpa identity verification.

76. Device Reuse

Device number reuse harus tidak dianggap identity equivalence.

77. Filesystem UUID

Gunakan UUID/equivalent filesystem identity jika available dan trustworthy.

78. Inode Reuse

Inode number dapat reused; pair dengan filesystem identity dan generation/change signals bila memungkinkan.

79. Metadata Change

Unexpected metadata change harus classification-aware.

80. Timestamp Granularity

Jangan bergantung hanya pada mtime karena granularity dan filesystem semantics berbeda.

81. File Size

Size check harus checked arithmetic dan bukan sole identity.

82. Hashing

Hash file sebelum delete umumnya tidak diperlukan dan mahal; hanya gunakan jika operation contract membutuhkan content identity.

83. Content Identity

Jika content identity diperlukan, gunakan bounded hashing and explicit cost budget.

84. Directory Identity

Directory inode/device dapat digunakan untuk detect replacement.

85. Parent Identity

Parent identity juga dapat diperlukan untuk mencegah path rebinding.

86. Permission Denied

Safety denial harus explicit `PermissionDenied`, bukan generic false.

87. Not Found

NotFound harus dibedakan dari AlreadySatisfied jika operation semantics mendukung idempotency.

88. Invalid Boundary

Boundary violation adalah hard denial.

89. Unsupported Primitive

Jika safety proof membutuhkan kernel primitive yang tidak tersedia, operation harus unsupported/denied sesuai risk class.

90. Unknown Safety

Unknown safety tidak boleh menjadi allow.

91. Safety Error Classification

Minimal:

- BoundaryViolation
- IdentityMismatch
- MountMismatch
- StorageMismatch
- TypeMismatch
- SymlinkRejected
- PermissionDenied
- ReadOnly
- Unsupported
- NotFound
- ResourceLimit
- Cancelled
- Timeout

92. Safety Audit

Audit harus menyimpan decision, reason code, identities/generations yang relevan, tanpa leaking sensitive paths.

93. Redaction

Full path hanya dicatat jika policy logging mengizinkan.

94. Security Logging

Safety denial penting harus observable tetapi tidak membanjiri log.

95. Metrics

Expose counters untuk boundary violations, identity mismatch, read-only, permission denial, stale generation, dan unsupported operations.

96. Repeated Failure

Repeated safety failures pada target yang sama dapat memicu target/catalog reconciliation.

97. Catalog Invalidation

Identity mismatch sebaiknya mark target stale dan request catalog refresh.

98. Planner Feedback

Safety failures dapat menjadi feedback ke planner/reconciler, tetapi tidak boleh silently rewrite plan.

99. Executor Boundary

Executor tidak boleh mempunyai alternate mutation path yang bypasses SafetyGate.

100. API Design

Recommended:

```rust
pub trait SafetyGate {
    fn validate(
        &self,
        operation: &PlannedOperation,
        context: &AuthorizedExecutionContext,
    ) -> Result<SafetyProof, SafetyError>;
}
```

101. Proof Consumption

Executor harus membutuhkan SafetyProof sebagai typed input.

102. Compile-time Boundary

Jika memungkinkan, Executor mutation method menerima proof type sehingga raw operation tidak dapat dieksekusi.

103. No Boolean Safety

Hindari API `is_safe() -> bool` untuk mutation authorization boundary.

104. Explicit Error

Safety API harus mengembalikan structured error.

105. Multi-target Operation

Operation yang menyentuh banyak target harus memperoleh safety proof per target/object atau proof aggregate yang explicit.

106. Partial Proof

Missing proof untuk satu object membuat keseluruhan destructive batch tidak executable jika atomicity policy mensyaratkan all-or-nothing.

107. Batch Delete

Batch deletion harus tetap bounded dan tidak memperluas proof scope tanpa validation.

108. Proof Scope

Proof scope harus sempit: object, operation, target, generation, dan deadline.

109. No Wildcard Proof

Proof seperti `all files under /cache` harus dihindari sebagai mutation authority.

110. Directory Proof

Jika recursive deletion digunakan, proof harus menyatakan recursive semantics dan subtree constraints.

111. Dynamic Directory

Jika subtree dapat berubah, executor harus revalidate each mutation or use safe kernel primitive that provides required semantics.

112. Cancellation

Cancellation tidak boleh bypass final safety; jika operation sudah mutated, result harus mengikuti unknown/reconciliation contract.

113. Timeout

Timeout sebelum mutation menyebabkan no mutation.

Timeout saat syscall dapat menghasilkan unknown outcome.

114. Unknown Outcome

Safety tidak boleh mengklaim success jika mutation result unknown.

115. Crash Window

Crash setelah safety check tetapi sebelum/selama syscall harus direconcile oleh recovery.

116. Recovery

Recovery harus menggunakan operation identity dan filesystem identity untuk menentukan actual state.

117. Idempotency

Delete operation harus dirancang agar repeated execution tidak memperluas scope.

118. Already Gone

Object yang sudah tidak ada dapat dianggap idempotently satisfied jika identity semantics mengizinkan.

119. Wrong Object Gone

Jika path sekarang menunjuk object lain, jangan menganggap success.

120. Safety Under Resource Pressure

Resource exhaustion tidak boleh membuat safety check dilewati.

121. Memory Failure

Jika proof materialization gagal karena memory, operation harus fail/blocked.

122. Stack/Depth

Traversal depth harus bounded.

123. Kernel Error Mapping

Map errno secara explicit; jangan collapse semua menjadi generic IO error.

124. Platform Abstraction

Linux-specific resolution APIs harus berada di platform adapter.

125. Test Double

SafetyGate harus dapat diuji dengan fake filesystem identity provider.

126. Race Harness

Test harus dapat melakukan replacement antara validation dan mutation.

127. Symlink Race Test

Uji perubahan intermediate component menjadi symlink setelah validation.

128. Mount Race Test

Uji mount replacement setelah planning.

129. Permission Race Test

Uji permission/ownership changes.

130. Device Reuse Test

Uji path same + different storage identity.

131. Property Test

Tidak ada mutation jika final identity mismatch.

132. Fuzzing

Fuzz relative path, malformed target descriptors, mount records, and platform error mappings.

133. Static Review

Cari semua syscall destructive dan pastikan seluruhnya berada di mutation boundary yang membutuhkan SafetyProof.

134. Grep Rule

Migration checklist harus dapat membuktikan tidak ada `remove_file`, recursive remove, rename destructive, truncate, atau equivalent mutation path yang bypass gate.

135. Definition of Done

Safety production-ready jika:

- TrustedRoot typed
- FD-relative resolution tersedia bila memungkinkan
- path escape ditolak
- symlink policy explicit
- mount boundary enforced
- identity revalidation implemented
- final gate dekat mutation
- proof typed
- no boolean safety authority
- force tidak bypass safety
- read-only enforced
- platform capability-aware
- unknown fail-closed
- audit/metrics tersedia
- crash/TOCTOU/race tests tersedia

136. Final Invariants

1. Raw path bukan safety proof.
2. TrustedRoot adalah boundary.
3. Candidate observation selalu potentially stale.
4. Final mutation membutuhkan SafetyProof.
5. Safety tidak memberi authorization.
6. Authorization tidak bypass safety.
7. Policy tidak bypass safety.
8. Force tidak bypass filesystem safety.
9. Identity mismatch selalu fail-closed.
10. Path replacement tidak boleh dianggap object yang sama.
11. Symlink traversal destructive harus explicit.
12. Cross-mount traversal harus explicit.
13. Read-only mount tidak boleh dimutasi.
14. Persisted identity harus direvalidasi setelah restart.
15. Catalog generation mismatch tidak boleh diabaikan.
16. SafetyProof memiliki scope terbatas.
17. SafetyProof tidak boleh dipakai ulang untuk object lain.
18. Executor tidak memiliki mutation path tanpa proof.
19. Unknown outcome tidak boleh dipublikasikan sebagai success.
20. Crash window harus dapat direconcile.
