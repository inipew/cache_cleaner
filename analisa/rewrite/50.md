50.md — Persistent Job State, Crash Recovery, Durable State, Atomic Commit, Job Resume Rules, Operation Outcome Reconciliation, Recovery After Executor Crash, and Durable Job Lifecycle Contract

Tujuan

Dokumen ini mendefinisikan bagaimana job dan hasil cleanup diperlakukan ketika daemon:

```
crash
restart
killed
kehilangan koneksi
kehilangan power
mengalami executor failure
mengalami filesystem/platform change
```

Prinsip paling penting:

```
"accepted job" != "safe to resume"
```

dan:

```
"syscall mungkin sudah dijalankan"
    !=
"operation pasti belum dilakukan"
```

Model utama:

```
Job
  │
  ▼
Durable State
  │
  ├──────────────┐
  ▼              ▼
Normal         Crash
  │              │
  ▼              ▼
Result       Recovery
                 │
                 ▼
           Reconciliation
                 │
         ┌───────┼────────┐
         ▼       ▼        ▼
      Verified  Unknown  Stale
         │       │        │
         └───────┼────────┘
                 ▼
            Final Result
                 │
                 ▼
           Fresh Job
```

1. Prinsip Durability

Durability digunakan untuk mempertahankan:

```
job identity
lifecycle state
generations
request metadata
execution progress
operation outcomes
final result
```

2. Durability Bukan Backup

Persistent state bukan filesystem backup.

Sistem tidak mencoba:

```
restore deleted files
```

3. Durability Bukan Execution Authority

Persistent state tidak boleh menjadi alasan untuk bypass:

```
Safety
Policy
Authorization
```

4. Persistent State Sebagai Evidence

Data persistence digunakan untuk menjawab:

```
"Apa yang diketahui sistem sebelum crash?"
```

bukan:

```
"Apa yang boleh dilakukan sekarang?"
```

5. Crash Changes Trust

Sebelum crash:

```
in-memory assumptions
```

Setelah restart:

```
assumptions harus dianggap stale
```

kecuali dapat dibuktikan kembali.

6. Recovery Default

Default:

```
do not resume destructive execution blindly.
```

18. Atomic State Transition

State transition harus atomic.

Contoh:

```
Executing
   │
   ▼
Verifying
```

Tidak boleh persistent storage menunjukkan:

```
Executing
```

sementara in-memory menunjukkan:

```
Completed
```

tanpa durable transition yang jelas.

19. Write-Ahead Principle

Sebelum melakukan operation yang membutuhkan recovery tracking:

```
persist enough state
```

agar crash recovery dapat mengidentifikasi:

```
operation in-flight
```

20. Critical Ordering

Untuk destructive operation:

```
persist intent/progress
     │
     ▼
execute
     │
     ▼
persist observed outcome
```

21. Why Intent Before Execution

Jika crash terjadi setelah mutation tetapi sebelum result persistence:

```
persisted state masih menunjukkan:
    operation in-flight
```

Maka recovery dapat melakukan reconciliation.

22. Never Mark Completed Before Mutation

Jangan:

```
persist Completed
    │
    ▼
delete
```

Jika crash di tengah:

```
database says success
filesystem says unknown
```

23. Never Assume "Not Persisted" Means "Not Executed"

Contoh:

```
execute unlink
    │
    ▼
crash
    │
    X
result not persisted
```

Recovery harus menganggap:

```
outcome = Unknown
```

     └── Audit
          │

196. Security Invariants

Invariant 1:

```
Crash tidak memberikan permission tambahan.
```

Invariant 2:

```
Restart menginvalidasi ephemeral authority.
```

Invariant 3:

```
Unknown outcome tidak boleh langsung di-retry.
```

Invariant 4:

```
Persisted plan bukan current authorization.
```

Invariant 5:

```
Generation mismatch mencegah blind resume.
```

Invariant 6:

```
Missing critical persistence evidence memblokir mutation.
```

Invariant 7:

```
Terminal result immutable.
```

Invariant 8:

```
Completion event hanya setelah durable result.
```

Invariant 9:

```
Recovery reconciliation read-only.
```

Invariant 10:

```
Package/mount/user changes dapat membuat operation stale.
```

Invariant 11:

```
Corrupted durable state menghasilkan fail-closed behavior.
```

Invariant 12:

```
Persistence failure tidak boleh menghasilkan unsafe continuation.
```

Invariant 13:

```
JobStore corruption tidak boleh menghasilkan arbitrary execution.
```

Invariant 14:

```
Fresh job menggunakan new JobId.
```

Invariant 15:

```
No destructive operation is replayed solely because it was previously authorized.
```
