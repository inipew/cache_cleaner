# 90.md — Backpressure, Work Admission, Queueing, dan Event Coalescing

## Tujuan

Daemon yang production-grade harus tetap bounded ketika event, request, atau workload datang lebih cepat daripada kemampuan executor menyelesaikannya.

Backpressure bukan sekadar optimasi. Ia menjaga agar tekanan workload tidak berubah menjadi:

- memory growth
- worker explosion
- event storm
- duplicate Job
- CPU churn
- I/O saturation
- thermal escalation

Prinsipnya:

```text
Input rate > processing rate
        ↓
bounded admission
        ↓
queue/coalesce/defer/reject
        ↓
system remains stable
```

## 1. Admission Terjadi Sebelum Work Explosion

Setiap sumber workload harus melewati admission:

```text
IPC request
scheduler trigger
event burst
recovery work
pressure reclaim
```

Tidak boleh setiap input langsung membuat worker atau Job baru.

## 2. Bounded Queue

Queue harus memiliki batas:

- max Job
- max pending operation
- max event
- max recovery item
- max memory

Ketika batas tercapai, behavior harus explicit:

```text
reject
coalesce
replace
defer
or apply backpressure
```

Jangan biarkan queue tumbuh tanpa batas.

## 3. Event Bukan Job

Event adalah signal.

Contoh:

```text
BatteryChanged
ScreenOff
MountChanged
StoragePressure
```

Tidak setiap event harus menghasilkan Job.

Scheduler mengevaluasi desired state setelah event dicoalesce.

## 4. Event Coalescing

Event burst:

```text
E1 E2 E3 E4 E5
```

dapat menjadi:

```text
one evaluation
```

Selama semantics memungkinkan, event terbaru dapat menggantikan event lama yang belum diproses.

## 5. Coalescing Tidak Boleh Menghilangkan Critical Event

Tidak semua event dapat dibuang.

Contoh `Shutdown`, recovery notification, atau authorization revocation mungkin membutuhkan processing explicit.

Event taxonomy harus menentukan:

- coalescable
- replaceable
- ordered
- critical

## 6. Manual Requests

Dua manual cleanup request terhadap scope yang sama dapat:

- deduplicate
- attach ke existing Job
- reject karena duplicate

sesuai idempotency contract.

Jangan membuat dua destructive execution hanya karena client mengirim dua request.

## 7. Scheduled Work Coalescing

Missed schedule tidak menghasilkan satu Job per missed tick.

Scheduler menentukan current eligibility lalu membuat work yang memang diperlukan sekarang.

## 8. Recovery Priority

Unresolved mutation recovery harus diprioritaskan dibanding optional new cleanup pada target yang sama.

Consistency lama tidak boleh ditutupi oleh workload baru.

## 9. Queue Classes

Dapat digunakan class terpisah:

```text
Recovery
Critical control
Manual
Scheduled maintenance
Background cleanup
```

Tujuannya agar background workload tidak menghalangi control/recovery.

## 10. Priority Bukan Bypass

Priority tidak boleh bypass:

- Safety
- Authorization
- dependency
- resource limits
- concurrency limits

Priority hanya mempengaruhi scheduling order.

## 11. Backpressure ke IPC

Jika daemon tidak dapat menerima Job baru, IPC harus memberikan typed response:

```text
Busy
QueueFull
RateLimited
Duplicate
Deferred
```

Jangan menerima request lalu diam-diam membuangnya.

## 12. Rate Limiting

Manual/IPC requests dapat dibatasi berdasarkan:

- client identity
- request type
- time window
- active Job count

Rate limiting melindungi daemon dari accidental loops maupun malicious clients.

## 13. Recovery Storm

Setelah crash, daemon dapat menemukan banyak non-terminal operations.

Jangan melakukan full recovery secara unbounded sekaligus.

Gunakan:

```text
bounded recovery batch
→ persist progress
→ yield
→ continue
```

## 14. Event Queue Overflow

Jika event queue penuh:

```text
mark reconciliation required
```

kemudian lakukan bounded authoritative snapshot/reconciliation.

Jangan berusaha mengejar setiap event yang hilang satu per satu jika current state dapat diperoleh langsung.

## 15. Snapshot Over Event History

Untuk state seperti battery, thermal, mount availability, current config, atau storage pressure, current snapshot biasanya lebih penting daripada seluruh event history.

Event memberitahu:

> "Mungkin ada perubahan."

Snapshot menentukan:

> "Keadaan sekarang bagaimana?"

## 16. Pressure Escalation

Storage pressure dapat mempunyai level:

```text
Normal
Warning
Critical
Emergency
```

Scheduler/policy menentukan response sesuai level.

Jangan membuat banyak Job hanya karena pressure signal berulang.

## 17. One Desired-State Job

Untuk trigger yang merepresentasikan desired state, lebih baik menjaga satu logical pending work:

```text
pressure = critical
       ↓
cleanup desired
       ↓
existing cleanup Job already pending
       ↓
update trigger context, don't duplicate Job
```

## 18. Work Deduplication

Deduplication key dapat berupa kombinasi:

```text
work type
scope/target identity
policy context
```

Jangan menggunakan path string sebagai satu-satunya key jika target identity tersedia.

## 19. Queue Memory

Queue entry harus kecil.

Jangan menyimpan seluruh Candidate set di event queue.

Gunakan JobId/OperationId/reference ke durable state bila memungkinkan.

## 20. Scanner Backpressure

Scanner menghasilkan candidate stream.

Planner/executor yang lambat tidak boleh menyebabkan scanner terus membaca filesystem tanpa batas.

Gunakan bounded channel:

```text
scanner → bounded queue → planner
```

Jika queue penuh, scanner block/yield.

## 21. Planner Backpressure

Planner juga tidak boleh membuat seluruh Plan tanpa mempertimbangkan executor capacity.

Jika plan sangat besar, gunakan chunking atau operation batching.

## 22. Executor Backpressure

Executor harus membatasi concurrent filesystem mutation.

Tidak boleh:

```text
100k candidates
→ 100k tasks
```

Lebih baik:

```text
bounded workers
→ bounded in-flight operations
```

## 23. Verifier Backpressure

Verifier juga bounded.

Jangan menjalankan 1000 verification tasks hanya karena 1000 mutation attempts selesai bersamaan.

## 24. Resource Manager Integration

Backpressure dan ResourceManager bekerja bersama:

```text
admission
 ↓
queue
 ↓
resource reservation
 ↓
execution
```

Resource unavailable berarti wait/defer, bukan membuat worker tambahan.

## 25. Queue Fairness

Priority queue harus mencegah starvation.

Recovery/control dapat mendapat reserved capacity.

Background cleanup dapat diberi aging agar tidak tertunda selamanya.

## 26. Cancellation as Backpressure

Jika Job sudah tidak relevan, cancellation lebih baik daripada membiarkannya memenuhi queue.

Contoh:

```text
pressure high
 ↓
cleanup Job running
 ↓
device becomes thermally constrained
 ↓
cancel/defer according to policy
```

Jika mutation sudah berjalan, cancellation tetap tunduk pada recovery semantics.

## 27. Thermal Backpressure

Thermal pressure dapat mengurangi concurrency:

```text
Normal → N workers
Warm → fewer workers
Hot → minimal work
Critical → stop optional work
```

Policy/safety tetap menentukan final decision.

## 28. Battery Backpressure

Battery condition dapat menunda optional cleanup.

Daemon tidak boleh membangunkan device hanya untuk mengejar queued background cleanup.

## 29. Power-Suspend Interaction

Backpressure harus tetap berlaku saat device suspend/resume.

Setelah resume:

```text
coalesce missed work
→ admission
→ run only required work
```

bukan membuat backlog execution burst.

## 30. Queue Persistence

Tidak semua queue perlu durable.

Classify:

```text
reconstructable event → memory only
recovery-critical work → durable
client Job identity → durable
```

Durability hanya digunakan jika recovery semantics membutuhkannya.

## 31. Queue Restart

Setelah restart, in-memory queue hilang.

Daemon rebuilds pending work dari durable state.

Jangan mencoba merekonstruksi exact event history jika current durable state cukup.

## 32. Admission Under Degraded State

Jika durable store, platform adapter, atau safety subsystem degraded, admission harus menjadi lebih konservatif.

Contoh:

```text
Safety unavailable
→ reject destructive work
```

## 33. Queue Full Semantics

Queue full bukan internal panic.

Ia harus menjadi domain result yang dapat diamati client/scheduler.

## 34. Thundering Herd

Hindari semua retry/job bangun pada waktu sama.

Gunakan bounded jitter pada retry/backoff jika diperlukan.

## 35. Retry Queue

Retry queue harus berbeda secara semantic dari new work.

Retry eligibility bergantung pada:

- failure class
- next retry time
- resource state
- safety
- authorization
- attempt limit

## 36. No Retry While Unsafe

Jika retry belum aman, jangan menghabiskan queue dengan retry cepat.

Work cukup disimpan sebagai deferred/retry-at.

Scheduler menunggu trigger/deadline yang tepat.

## 37. Queue Observability

Expose metrics seperti:

- queued jobs
- active jobs
- rejected requests
- coalesced events
- dropped/reconciled events
- retry queue size
- oldest queue age
- queue saturation

Metrics bukan source of truth.

## 38. Bounded Shutdown

Shutdown harus menghentikan admission baru lalu menangani queued/active work sesuai policy.

Urutan:

```text
stop admission
→ signal cancellation
→ finish safe critical sections
→ reconcile unresolved operations
→ release resources
→ persist final state
→ exit
```

## 39. Definition of Done

Backpressure production-ready jika:

- semua input memiliki admission path
- queue bounded
- event dan Job dibedakan
- event coalescing tersedia
- critical event tidak hilang
- recovery priority jelas
- worker concurrency bounded
- scanner/planner backpressure tersedia
- IPC busy/full semantics typed
- retry queue bounded
- thermal/battery interaction jelas
- suspend/resume tidak membuat burst
- restart dapat rebuild durable work
- queue metrics tersedia

## Final Invariants

1. Input rate tidak boleh menyebabkan resource unbounded.
2. Event tidak otomatis menjadi Job.
3. Queue selalu bounded.
4. Critical event tidak boleh hilang karena coalescing.
5. Duplicate work harus dideduplicate.
6. Recovery unresolved mutation mendapat priority yang sesuai.
7. Priority tidak bypass safety/authorization.
8. Scanner harus tunduk pada downstream backpressure.
9. Planner tidak membuat unbounded in-flight work.
10. Executor concurrency bounded.
11. Verifier concurrency bounded.
12. Resource unavailable berarti wait/defer, bukan worker explosion.
13. Thermal/battery pressure dapat mengurangi work.
14. Suspend tidak boleh menghasilkan missed-work storm.
15. Retry hanya saat eligible.
16. Queue full adalah typed domain condition.
17. Durable work direconstruct dari state, bukan fragile event history.
18. Shutdown menghentikan admission baru.
19. Backpressure harus tetap fail-safe saat subsystem degraded.
20. Observability tidak menjadi correctness dependency.
