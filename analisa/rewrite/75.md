75.md — Verifier, Postcondition, Before/After State, Unknown Outcome, Reconciliation, Idempotency, Accounting, and Terminal Result Contract

Tujuan

Verifier menentukan apakah actual filesystem state setelah execution memenuhi postcondition operation. Verifier adalah sumber kebenaran untuk final operation result setelah syscall.

Pipeline:

Executor Receipt → Verifier → Reconciliation bila perlu → Operation Result → Job Aggregation

1. Verification Is Postcondition Checking

Verifier tidak sekadar memeriksa errno == 0.

2. Syscall Success != Operation Success

A successful syscall adalah evidence, bukan selalu final proof.

3. Postcondition

Setiap operation harus mendefinisikan expected postcondition.

4. DeleteFile Postcondition

Object dengan expected identity tidak lagi ada.

5. DeleteDirectory Postcondition

Directory target dan required subtree state memenuhi deletion semantics.

6. Reclaim Postcondition

Reclaim operation harus memiliki platform-specific measurable postcondition.

7. Maintenance Postcondition

TRIM/ZRAM/F2FS/etc harus mempunyai explicit verification semantics.

8. Verification Result

Recommended:

```rust
pub enum VerificationResult {
    Verified,
    AlreadySatisfied,
    Failed(VerificationFailure),
    Unknown(VerificationUnknown),
}
```

9. Verified

Observed state memenuhi seluruh postcondition.

10. AlreadySatisfied

Desired state sudah tercapai tanpa mutation yang dilakukan attempt saat ini, jika identity semantics mendukung.

11. Failed

Observed state bertentangan dengan postcondition.

12. Unknown

Tidak cukup evidence untuk menentukan state dengan aman.

13. Unknown != Failed

Unknown harus dipertahankan karena recovery semantics berbeda.

14. Unknown != Success

Unknown tidak boleh dihitung sebagai verified.

15. Before State

Verifier harus menggunakan before-state observation bila dibutuhkan untuk identity matching.

16. After State

Verifier mengambil fresh observation setelah executor receipt.

17. Fresh Observation

Jangan menggunakan Candidate metadata lama sebagai after-state proof.

18. Identity

Object absence harus dinilai terhadap expected identity/path binding.

19. Path Reuse

Jika path sekarang menunjuk object berbeda, operation bukan verified.

20. Object Gone

Jika expected object gone, deletion dapat verified/AlreadySatisfied sesuai execution history.

21. Wrong Object

Different object at same path = failure/stale, bukan success.

22. Type Change

Expected file menjadi directory/symlink berarti postcondition mismatch.

23. Symlink

Verifier harus memastikan symlink semantics sesuai operation.

24. Directory Empty

Empty directory tidak sama dengan directory absent jika postcondition adalah full deletion.

25. Recursive Delete

Verifier harus menentukan subtree postcondition secara explicit.

26. Verification Depth

Recursive verification harus bounded.

27. Verification Budget

Object count, bytes, depth, and time must be bounded.

28. Verification Timeout

Timeout menghasilkan Unknown kecuali postcondition sudah terbukti sebelum deadline.

29. Verification Cancellation

Cancellation dapat menghasilkan Unknown jika observation belum complete.

30. Permission Error

Permission denied saat verification = Unknown atau Failed sesuai ability to prove state; default conservative.

31. Not Found

NotFound pada expected object dapat membuktikan absence jika path/identity semantics tepat.

32. Parent Missing

Missing parent dapat satisfy deletion postcondition for descendant only if identity-bound reasoning proves it.

33. Mount Change

Mount change during verification invalidates assumptions and usually produces Unknown/Stale.

34. Storage Change

Storage identity mismatch must never become Verified.

35. Catalog Generation

Verification must bind to relevant TargetId/CatalogGeneration or revalidated equivalent identity.

36. Config Generation

If postcondition semantics depend on config, preserve ConfigGeneration.

37. Authorization

Verifier does not create or renew authorization.

38. Safety

Verifier does not replace final safety checks for a new mutation attempt.

39. Reconciliation

Unknown result triggers Reconciler when safe classification is possible.

40. Reconciliation Purpose

Reconciler determines actual state and whether operation may be marked satisfied, retried, blocked, or RecoveryRequired.

41. Reconciliation Read-only

Normal reconciliation should observe, not mutate.

42. Reconciliation Retry

Retry mutation only after reconciliation proves safe and fresh authorization/safety are obtained.

43. Crash Window

Crash after syscall-start and before receipt publication must be treated as Unknown.

44. Durable Journal

Executor journal boundary enables recovery to know whether syscall may have started.

45. No False Failure

Do not mark Failed merely because receipt is missing.

46. No False Success

Do not mark Verified merely because an attempt record says started/completed.

47. Idempotency

Verifier must support repeated execution semantics.

48. Already Gone

A delete target already gone can be idempotently satisfied when expected identity is no longer present.

49. Replacement Present

If replacement object exists, it must not satisfy deletion of original identity.

50. Operation Identity

Verification binds to OperationId/expected identity.

51. Attempt Identity

AttemptId distinguishes execution attempts but does not change logical postcondition.

52. Partial Operation

A recursive operation can have partial deletion and must report explicit partial state.

53. Partial State

Partial is not success unless operation contract explicitly defines best-effort success semantics.

54. Best-effort

Best-effort must report skipped/failed children separately.

55. Accounting

Freed bytes are verified/accounted after postcondition where possible.

56. Byte Accounting

Use before-size observed data only as an estimate; actual reclaimed bytes may differ.

57. Filesystem Free Space

Free-space delta is supplementary evidence, not object deletion proof.

58. Sparse Files

Logical size and blocks freed can differ.

59. Compression/Dedupe

Physical storage impact may differ from logical bytes.

60. Accounting Model

Distinguish:

- logical bytes removed
- physical blocks potentially reclaimed
- filesystem free-space delta

61. No Negative Overflow

Accounting uses checked/saturating arithmetic with explicit overflow handling.

62. Duplicate Accounting

Retries/AlreadySatisfied must not double-count logical freed bytes.

63. Operation Result

Result must be immutable after finalization.

64. Result States

Suggested:

- Verified
- AlreadySatisfied
- Failed
- Cancelled
- TimedOut
- Unknown
- RecoveryRequired

65. Terminal Classification

Only lifecycle state machine can transition operation/job into terminal state.

66. Verifier Output

Verifier returns result evidence; state machine persists it.

67. Evidence

Evidence may include:

- final object type
- identity
- metadata
- absence/presence
- platform result code

68. Evidence Redaction

Do not expose sensitive full paths unnecessarily.

69. Evidence Immutability

Verification evidence is append-only/audit-safe.

70. Timestamp

Record monotonic duration and wall timestamp for audit where useful.

71. Verification Deadline

Verification has its own bounded deadline derived from job/operation deadline.

72. No Infinite Verify

Repeated verification failures must stop after bounded attempts.

73. Retry Classification

Retry verification only for transient observation errors.

74. Permission Retry

Do not infinite retry permission errors.

75. Mount Retry

Mount changes should trigger catalog reconciliation, not blind verification retry.

76. Identity Mismatch

Identity mismatch is stale/failure and must not be retried against replacement object.

77. Resource Limits

Verifier uses ResourceManager for memory/IO/time budgets.

78. Concurrency

Verification may run parallel for independent operations if resource policy permits.

79. Same Target

Concurrent verification must not accidentally invalidate each other's operation semantics.

80. Locking

Verifier should acquire observation/resource locks if platform semantics require it.

81. No Mutation Lock Assumption

A verification lock is not necessarily a mutation exclusion lock.

82. Postcondition Version

Postcondition schema should be versioned.

83. Operation Version

Verifier must understand operation schema version or return Unsupported.

84. Unsupported

Unsupported postcondition is not Verified.

85. Platform Adapter

Platform-specific verification logic belongs in adapter.

86. Generic Verifier

Generic verifier coordinates expected vs observed state.

87. Delete Adapter

Android/Linux filesystem adapter supplies safe stat/open/readlink/mount identity operations.

88. Maintenance Adapter

System maintenance verification must expose explicit status/facts.

89. TRIM

TRIM completion semantics depend on platform; do not infer success solely from command exit code if stronger verification is available.

90. ZRAM

ZRAM configuration verification should read actual kernel state when supported.

91. F2FS

F2FS maintenance verification should use supported filesystem signals.

92. Unknown Platform

If platform cannot provide postcondition evidence, result should be Unknown/Unsupported rather than optimistic success.

93. State Machine Integration

Verifier result feeds Attempt state transition.

94. Attempt Success

Attempt success only after Verified/AlreadySatisfied according to operation semantics.

95. Attempt Unknown

Unknown moves operation toward Reconciling/RecoveryRequired.

96. Job Aggregation

One Unknown operation prevents Job from being reported fully Completed unless job policy explicitly supports partial completion and the unknown is resolved.

97. Partial Job

Job result must enumerate counts by verified/already-satisfied/failed/unknown/skipped.

98. User Output

CLI/UI should distinguish:

- removed
- already gone
- skipped
- failed
- unknown/recovery

99. No Misleading 100%

Progress 100% means attempts processed, not necessarily all postconditions verified.

100. Final Completion

Job Completed means all required postconditions are satisfied according to job contract.

101. Completion Barrier

State machine must wait for verifier/reconciliation before terminal success.

102. Crash Recovery

On restart, in-flight verification must be resumed/reconciled from durable state.

103. Blind Resume Prohibited

Do not rerun mutation merely because verification record is missing.

104. Reconciliation Policy

Recovery may choose:

- mark satisfied
- retry with fresh plan/auth/safety
- mark failed
- require manual recovery

105. Manual Recovery

Manual recovery must be explicit and audited.

106. No Arbitrary Cleanup

Recovery cannot become an unrestricted cleanup interface.

107. Property Testing

Properties:

- Verified implies postcondition observed
- Unknown never implies success
- replacement object never satisfies original deletion
- accounting is idempotent

108. Race Testing

Simulate:

- object deletion before verification
- replacement after mutation
- rename
- mount replacement
- permission change

109. Crash Testing

Inject process termination at every journal boundary.

110. Fuzzing

Fuzz verifier DTOs, filesystem metadata, malformed platform responses, and deep trees.

111. Differential Tests

Compare adapter verification against known filesystem behavior on Linux test fixtures.

112. Determinism

Same before/after evidence must produce same machine result.

113. Definition of Done

Verifier production-ready jika:

- explicit postconditions
- fresh observation
- identity-aware
- unknown outcome
- reconciliation integration
- bounded verification
- retry classification
- accounting separation
- immutable evidence
- crash recovery
- platform abstraction
- no false success
- no double accounting
- race/crash/property/fuzz tests

114. Final Invariants

1. Verifier memeriksa postcondition.
2. Syscall success bukan otomatis operation success.
3. Fresh after-state diperlukan.
4. Expected identity harus dipertahankan.
5. Replacement object tidak memenuhi original postcondition.
6. Unknown bukan success.
7. Unknown bukan Failed secara otomatis.
8. Permission uncertainty fail-closed.
9. Mount/storage identity mismatch tidak Verified.
10. Recursive verification bounded.
11. Verification deadline enforced.
12. Verification retry bounded.
13. Identity mismatch tidak blind retry.
14. Verifier tidak melakukan authorization.
15. Verifier tidak menggantikan SafetyGate.
16. Unknown memicu reconciliation.
17. Crash window diperlakukan Unknown.
18. AlreadySatisfied harus identity-aware.
19. Accounting tidak boleh double count.
20. Logical bytes dan physical free space dibedakan.
21. Result immutable setelah finalization.
22. Job Completed membutuhkan required postconditions satisfied.
23. Progress 100% bukan bukti success.
24. Recovery tidak boleh menjadi arbitrary mutation path.
25. Platform unsupported tidak boleh dilaporkan success.
